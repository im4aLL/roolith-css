Layout

roolith css ships a centered container, a twelve column grid, and a small application shell built on the same grid. The grid is written as a real CSS grid, and the float based grid still compiles if you ask for it.

class: Multiple classes - defined in modules/_css-grid.scss, modules/_grid.scss, modules/_layout.scss
$grid-layout defaults to css-grid . The float grid is legacy, and roolith prints a build warning when you select it.

Container

.container caps its content at var(--r-global-width) and centers it with auto margins. The token is generated from $container-width, which defaults to rem(1200).

Content inside .container
HTML 
<div class="container">
    <div class="box box-small">
        <div class="box-body">Content inside .container</div>
    </div>
</div>

The demo adds full-width, the typography width utility, so the container stretches across the demo box. Without it the container has no width of its own, so inside the flex demo box it only takes the width of its content. It is demo scaffolding only: .container sets a max width and auto margins, no container rule reads full-width, and the snippet above leaves it out.

The row and column system

.row is a grid with $grid-column-count equal tracks, twelve by default. Every direct child is a grid item, so a span class works on a div, a section, or a form field without extra markup.

Spans are small-1 through small-12, and the same pattern repeats for the medium- and large- prefixes. Keep .columns on the item as the classic marker - it does nothing under the CSS grid, but the same markup then still works if you switch to the float grid.

Breakpoints

The grid emits three prefix groups: small- with no media query, medium- from 640px, and large- from 1024px. There are no xlarge- column classes.

Any item that carries a medium- or large- class starts at full width and only takes its span when the breakpoint applies, so the stack order is mobile first. The example below still writes small-12 to state the intent.

large-4 medium-6 small-12
large-4 medium-6 small-12
large-4 medium-6 small-12
HTML 
<div class="row">
    <div class="columns large-4 medium-6 small-12">...</div>
    <div class="columns large-4 medium-6 small-12">...</div>
    <div class="columns large-4 medium-6 small-12">...</div>
</div>
Breakpoint Width Grid prefix
small 0 Yes, no media query
medium 640px Yes
large 1024px Yes
xlarge 1200px No column classes
xxlarge 1440px No column classes

xlarge and xxlarge are still available to the breakpoint mixin and to the show and hide helpers, so a custom component can use them even though the grid does not.

Offsets

An offset pushes an item to a later column line. The available range is 1 through 11 per prefix, matching a twelve column row.

large-6 large-offset-3
HTML 
<div class="row">
    <div class="columns large-6 large-offset-3">...</div>
</div>

Add newrow to an item to pin it back to column line 1. In the CSS grid that starts a fresh row immediately; in the float grid it clears the previous float.

Push and pull

Push and pull change the visual order without touching the markup. Each span records its column count, so a push of N shifts the item right by N columns, calculated from its own width, and a pull does the same to the left.

large-6 large-push-6 (renders right)
large-6 large-pull-6 (renders left)
HTML 
<div class="row">
    <div class="columns large-6 large-push-6">Renders on the right</div>
    <div class="columns large-6 large-pull-6">Renders on the left</div>
</div>

Use equal spans when you swap two neighbours, otherwise the shifted item overshoots the row. Because push and pull only change the offset, the source order stays intact for screen readers and keyboard users.

Gutters and nesting

A gutter is the space between columns. $grid-gutter-size defaults to rem(20) and feeds a three entry map for small, medium, and large. The row carries half a gutter as padding and so does every item, which puts a full gutter between neighbours and keeps the outer content aligned with the container edge.

One
Two
Three
HTML 
<div class="row">
    <div class="columns large-4">One</div>
    <div class="columns large-4">Two</div>
    <div class="columns large-4">Three</div>
</div>

A row inside a row drops its own padding and pulls back by half a gutter with negative margins, so nested content lines up at any depth. Wrap a nested row in .column when it sits outside a row and needs the full gutter on both sides.

HTML 
<div class="row">
    <div class="columns large-6">
        <div class="row">
            <div class="columns large-6">Half of the half</div>
            <div class="columns large-6">Half of the half</div>
        </div>
    </div>
</div>

<div class="column">
    <div class="row">
        <div class="columns large-12">Full gutter on both sides</div>
    </div>
</div>

Application layout

.layout is a two column shell for admin style screens. It is a grid with a sidebar column and a content column, plus a row for the header and a row for the body, and it fills the viewport with min-height: 100vh . Below 1024px the sidebar column uses the compact width; from 1024px up it uses the full sidebar width.

The header spans both columns and is a grid of its own. Its primary cell holds the logo and the sidebar toggle, and its secondary cell holds search, navigation, and the user menu. Add is-sticky to the header to pin it to the top of the viewport.

  • .layout-primary is the left column and draws the right border.
  • .layout-sidebar is the wrapper used for the sidebar content. It carries no rules of its own, so the column spacing comes from .layout and the navigation inside it.
  • .layout-secondary is the content column with rem(20) of padding and its own background token.
  • .layout-compact on the shell overrides --r-layout-sidebar-width with the compact width and hides the header logo.
There is no inline demo for the shell: it is min-height: 100vh by design, so it would take over the viewport. The classes below are the full scaffold.
HTML 
<main class="layout">
    <header class="layout-header is-sticky">
        <div class="layout-header-primary">
            <a class="layout-header-logo" href="/">Logo</a>
            <button class="layout-header-sidebar-toggle" type="button">Menu</button>
        </div>

        <div class="layout-header-secondary">
            <form class="form layout-header-search" action="/search" role="search">

            </form>

The legacy float grid

Setting $grid-layout to traditional swaps modules/_css-grid.scss for modules/_grid.scss . Class names stay the same - spans, offsets, push, pull, .container, and .newrow - but the mechanics change: items float, spans become width percentages, offsets become margin-left, and the row uses a clearfix.

The traditional grid is legacy. New work should stay on the default css-grid layout.
SCSS 
@use 'roolith-css/src/sass/settings' with (
    $grid-layout: traditional
);
@use 'roolith-css/src/sass/roolith';

The float grid also styles .columns with float: left and half a gutter of padding, so a row of floated columns needs .columns on every item to keep its shape.

Accessibility

The layout only controls geometry, so the structure and the reading order are yours to get right.

  • Build the page from real landmarks - header, nav, main, and footer - and keep a single h1 per page. The shell classes carry no landmark semantics of their own.
  • Keep the DOM order meaningful. The CSS grid and the push and pull modifiers can place an item visually before its neighbour while leaving the source order untouched, and assistive technology follows the source order.
  • Do not rely on visual order alone in a responsive layout. When a column reflows or a region moves, check that the reading sequence still makes sense without the styling.
  • Do not give .container or a grid item a fixed pixel width or a user-scalable=no viewport, so the page can still zoom and reflow at 400% without horizontal scrolling.
  • Keep focus visible when a layout region scrolls. The base layer outlines focusable elements on :focus-visible, so do not remove that outline, and avoid overflow: hidden on a region that can receive focus.

Class reference

Grid classes are emitted for the small, medium, and large prefixes. The layout classes belong to the application shell.

Class Applies Notes
.container Wrapper Caps at var(--r-global-width) and centers with auto margins.
.row Grid Twelve equal tracks, items aligned to start, half a gutter of padding.
.columns Item Column marker. Floats in the legacy grid, no rules under css-grid.
.column Wrapper Full gutter on both sides for a nested row that sits outside a row.
.small-1 Span Through .small-12 , no media query. Also medium and large.
.small-offset-1 Offset Through 11. Also .medium-offset-* and .large-offset-*.
.small-push-1 Order Shifts right by its own width. Also .small-pull-* and the medium and large sets.
.newrow Item Starts a new grid row, or clears floats in the legacy grid.
.layout Shell Two column grid with a header row and a content row, min-height 100vh.
.layout-header Shell Spans both columns and splits into primary and secondary cells.
.is-sticky Header Sticky header at the top of the viewport with z-index 1000.

.layout-sidebar Shell Sidebar wrapper used in the markup. No rules of its own.
