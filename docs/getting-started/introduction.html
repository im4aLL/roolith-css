Introduction

roolith is a responsive CSS framework written in SCSS and shipped as one stylesheet. A typographic base, a 12 column grid, and a component set share a single token layer, so theming and dark mode come from CSS custom properties instead of duplicate stylesheets.

class: Multiple classes - defined in src/sass/roolith.scss

What is roolith

roolith is a responsive CSS framework. The entry point, src/sass/roolith.scss, composes a reset, a typographic base, layout, state rules, the component modules, and the block patterns into one stylesheet.

Every visual decision is a CSS custom property. Colors, surfaces, text, borders, radii, and component details all resolve through tokens, so .theme-dark or an operating system preference re-themes the page without a second stylesheet.

The build output is CSS only. roolith ships no JavaScript: components that change state are styled against class hooks such as .active, .open, and .loading, and you attach the behavior with the script your project already loads.

Who it is for

roolith fits server-rendered apps, static sites, and admin screens where markup is written by hand or generated from templates. It assumes you want a small, readable CSS base that you can extend with your own rules.

It is a poor fit if you want a class for every property. There is no utility explosion here: you get base element styles, a grid, and components, then your own product CSS on top. If you prefer utility-first class lists, a utility framework will suit you better.

Teams that already use Sass get the most out of it, because the source is plain SCSS with a settings file and a small function and mixin set. Plain HTML projects can use the compiled stylesheet and ignore Sass entirely.

Design principles

A few decisions shape the rest of the framework.

  • Tokens before values. Components reference semantic tokens such as --r-surface-raised and --r-text-muted instead of literal colors.
  • Semantic class names. Classes describe a role - .card, .message-info, .button-primary - so markup stays readable.
  • Low specificity. The reset is written with :where(), which keeps element resets at zero specificity, so your own rules win without !important.
  • Accessibility defaults. Focusable controls get a :focus-visible ring, prefers-reduced-motion is honored globally, and links inside prose containers are underlined for WCAG 1.4.1.
  • Mobile first. Breakpoints start at small (0), then medium (640px) and large (1024px), and the layout is a 12 column CSS grid.
  • Progressive enhancement. Modern CSS such as color-mix() drives the neutral ramp, and optional properties such as text-box-trim in .badge degrade without breaking layout.

Release notes

Version 4.0.0 ships the token layer, dark mode, and the CSS grid layout.

HTML 
<!doctype html>
<html lang="en">
    <head>
        <meta charset="utf-8" />
        <meta name="viewport" content="width=device-width, initial-scale=1" />
        <title>Release notes</title>
        <link rel="stylesheet" href="roolith-4.1.0.min.css" />
    </head>
    <body>
        <main class="container">
            <div class="card">
                <div class="card-body">
                    <h2 class="h4">Release notes</h2>
                    <p class="card-text">Version 4.0.0 ships the token layer, dark mode, and the CSS grid layout.</p>
                    <button class="button button-primary" type="button">Read the notes</button>
                </div>
            </div>
        </main>
    </body>
</html>

Browser support

roolith targets current evergreen browsers: recent Chrome, Edge, Safari, and Firefox. Internet Explorer is not supported.

The hard baseline is color-mix(). The neutral ramp, every tinted surface, and most hover states are built with it, so a browser without support renders those colors as invalid. :has() is used by the radio group and the combo box submenu for the same reason.

Optional properties degrade on their own. text-box-trim, used only in .badge, trims the line box where it is supported and leaves normal spacing where it is not.

If you have to support an older browser, the fix belongs in your own stylesheet: override the affected component tokens with plain color values rather than patching the framework output.

External resources

roolith does not ship an icon font, and it does not bundle a webfont. Two external stylesheets fill both gaps: Iconoir for icon classes, and Inter for the default typeface.

The base font token, --r-global-base-font, defaults to 'Inter', sans-serif, so the Google Fonts link is what makes Inter render instead of the system fallback. The framework's bold weight is 600, which is why the link requests 400 and 600.

HTML 
<link rel="stylesheet" href="https://cdn.jsdelivr.net/gh/iconoir-icons/iconoir@main/css/iconoir.css" />
<link href="https://fonts.googleapis.com/css2?family=Inter:wght@400;600&display=swap" rel="stylesheet" />

Load both after the framework stylesheet and before your own, so your rules keep the last word. Iconoir supplies classes such as iconoir-home; use them on an <i> or <span> where you would normally place an icon.
