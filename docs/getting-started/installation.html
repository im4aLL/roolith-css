Installation

roolith installs as an npm package whose entry point is the SCSS source. You can compile that source in your own pipeline, or build the framework once and link a single CSS file. Both routes expose the same token layer.

class: Multiple classes - defined in src/sass/roolith.scss

Install from npm

roolith-css is published on npm. The package entry declared in package.json is ./src/sass/roolith.scss, and the prebuilt stylesheet ships alongside it at dist/roolith-4.0.0.min.css.

You can compile the SCSS in your own pipeline or copy the prebuilt file into your assets and link it. The next two sections cover the built stylesheet and the SCSS source.

Shell 
npm i roolith-css

Link the built stylesheet

The build writes one file, dist/roolith-4.0.0.min.css. Both parts of that name come from the package: the Vite config names assets [name]-[version].min.css and the input is roolith.

Copy the file wherever your static assets live, then link it once per page. Everything below is rendered by that stylesheet alone, with no page specific CSS.

Primary Success
HTML 
<link rel="stylesheet" href="roolith-4.0.0.min.css" />
This documentation site loads the stylesheet as ../roolith-4.0.0.min.css, which resolves to docs/roolith-4.0.0.min.css. A CDN link will replace it later; until then point your pages at the file you build or copy.

Use the SCSS source

Import the entry point from your own Sass file. roolith.scss loads main and runs roolith-everything(), so one @use emits the token layer, the reset, base styles, modules, blocks, layout, and state rules in one pass.

The import resolves from node_modules. Bundlers such as Vite resolve package paths for you; the Sass CLI needs --load-path=node_modules.

SCSS 
@use 'roolith-css/src/sass/roolith.scss';

To decide what the build emits, load main instead. It declares the same mixins but writes nothing on its own, so the includes you write become the stylesheet. It owns no variables, so overrides go through settings, which you load with a with block before main.

SCSS 
@use 'roolith-css/src/sass/main' as r;

@include r.roolith-base();
@include r.roolith-modules();
@include r.roolith-extended-modules();
@include r.roolith-blocks();
@include r.roolith-layout();
@include r.roolith-state();

The first four groups cover the tokens, reset, typography, components, and composed blocks. roolith-layout() adds the grid and the application scaffold, and roolith-state() adds the show, hide, and .is-* helpers, so drop either include only when the page does not need them. roolith-everything() calls all six in that order.

The compiled output still declares the token layer as CSS custom properties, so runtime theming works the same way whether you compile the SCSS or link the built file. Overrides stay plain CSS either way.

Build from source

Clone the repository, install the dev dependencies, then build. Vite writes the stylesheet to dist/, names it after the package name and version, and adds a banner comment with the version and build date.

npm run dev starts the Vite dev server, which serves the demo pages in the repository root and recompiles the SCSS on change. npm run build performs the production build and empties dist/ first.

Shell 
npm install
npm run dev
npm run build

Autoprefixer runs through the PostCSS config in the repository root, so the build output carries the vendor prefixes that the source does not spell out.

CSS variable dump

Two scripts print the token layer to a stylesheet you can read, diff, and hand to a designer. npm run css-vars writes only the theme tokens declared on :root, .theme-light, and .theme-dark.

npm run css-vars:all includes every custom property the framework sets, including the ones scoped to component rules, such as --grid-span on the grid classes.

Shell 
npm run css-vars
npm run css-vars:all
node scripts/generate-css-variables.mjs --out tokens.css

Both scripts write dist/roolith-variables.css by default and accept --out for another path. A build empties dist/, so run the dump after npm run build when you want the token list next to the compiled CSS.

HTML document shell

A roolith page needs the doctype, a viewport meta tag so the grid collapses on phones, and one stylesheet link. Put a theme class on <html> only when you want to force a mode.

HTML 
<!doctype html>
<html lang="en">
    <head>
        <meta charset="utf-8" />
        <meta name="viewport" content="width=device-width, initial-scale=1" />
        <title>My page</title>
        <link rel="stylesheet" href="roolith-4.0.0.min.css" />
    </head>
    <body>
        <main class="container">
            <h1>My page</h1>
            <p>Content starts here.</p>
        </main>
    </body>
</html>

Leave the theme class off to follow the operating system through prefers-color-scheme. Add class="theme-light" or class="theme-dark" to pin a mode; the rules behind both are covered in Theming.
