Theming

Every color, radius, and surface in roolith comes from a CSS custom property. Tokens are declared in layers, so you can restyle one component, a whole page, or both themes without editing a single component rule.

class: Multiple classes - defined in src/sass/_css-var.scss

Token layers

Appearance is declared in three layers. Palette primitives hold raw colors, semantic tokens name the job a color does, and component tokens bind one part of a component to a semantic token.

Palette primitives come from src/sass/_settings.scss and are emitted by palette-primitives() . Each palette color gets three tokens: the fill, the color used on top of the fill, and the color used when the palette color is text.

Primary --r-color-primary
Secondary --r-color-secondary
Tertiary --r-color-tertiary
Info --r-color-info
Success --r-color-success
Warning --r-color-warning
Danger --r-color-danger
Link --r-color-link

The neutral ramp is generated, not listed: --r-color-neutral-50 through --r-color-neutral-800 are mixed from --r-color-neutral with color-mix() , and --r-color-neutral-900 is the dark color from settings.

CSS 
:root {
    --r-color-primary: #4a5cd0;
    --r-color-primary-on: #ffffff;
    --r-color-primary-text: var(--r-color-primary);
    --r-color-neutral: #ffffff;
    --r-color-neutral-100: color-mix(in srgb, var(--r-color-neutral), black 4%);
    --r-color-neutral-800: color-mix(in srgb, var(--r-color-neutral), black 70%);
    --r-color-neutral-900: #1e2128;
}

Semantic tokens map primitives onto surfaces, text, and borders. Components read these almost everywhere, so one surface change re-themes every card, modal, and drawer at once. --r-accent and its -on and -text partners are aliases of the primary palette entry, which is what most interactive components use.

CSS 
:root {
    --r-surface-page: var(--r-color-neutral);
    --r-surface-raised: var(--r-color-neutral);
    --r-surface-muted: var(--r-color-neutral-100);
    --r-text: var(--r-color-neutral-900);
    --r-text-muted: var(--r-color-neutral-800);
    --r-border: var(--r-color-neutral-300);
    --r-link: var(--r-color-link);
    --r-accent: var(--r-color-primary);
}

Component tokens are the last layer, declared in src/sass/_component-var.scss . A component token normally points at a semantic token, so a change at the top flows down without touching the component file. Names starting with --_r- are internal, such as --_r-on-surface , and may change between releases.

Theme scopes

Theme tokens are emitted for three scopes: :root , .theme-light , and .theme-dark . The first two share the light palette, and .theme-dark replaces the palette, the semantic mapping, and the component tokens that depend on them.

Shared tokens such as --r-global-border-radius and --r-accent are declared on all three scopes, so a theme class never leaves a token undefined. Each theme also sets color-scheme , which tells the browser how to render scrollbars, form controls, and the canvas.

When no explicit class is present the framework follows the operating system, through @media (prefers-color-scheme: dark) { :root:not(.theme-light) { ... } } . .theme-light opts a page out of that automatic switch, and .theme-dark forces dark.

The scopes are ordinary class selectors, so a theme also applies to a subtree, as the two panels above show. That is useful for previews and side-by-side comparisons, but the document root is the normal place for it.

Overriding tokens

Load your overrides after the framework stylesheet and override at :root . At that level the framework's aliases - --r-accent , --r-button-radius , --r-card-radius - are declared on the same element, so they resolve against your new values.

Keep contrast pairs together. --r-color-primary is the fill, --r-color-primary-on is the text placed on it, and --r-color-primary-text is the tint used when the palette color becomes text, as in an outline button label or a badge.

Surfaces and text are the fastest way to match a product palette: --r-surface-page , --r-surface-raised , --r-text , and --r-text-muted cover most of the interface. --r-global-border-radius defaults to 0.5rem and feeds every component radius token.

A scoped override recalculates only the tokens a component rule reads directly. An alias declared at the theme scope keeps the value it computed there, so overriding --r-global-border-radius on a wrapper will not move --r-button-radius or --r-card-radius ; repeat the aliases you care about inside the scope.

The right-hand card above repeats the primary and accent aliases, which is why its badge and button change color while its radius stays at the theme value. Structural tokens belong at :root or on <html> , where the aliases are declared.

CSS 
.promo {
    --r-color-primary: #f59e0b;
    --r-color-primary-on: #1f2937;
    --r-color-primary-text: #b45309;
    --r-accent: #f59e0b;
    --r-accent-on: #1f2937;
    --r-accent-text: #b45309;
}

Base tokens to override

Most product themes start and end with this set. The palette primitives, the surface, text, and border roles built on them, and a few structural tokens cover the bulk of an interface, because every component token above them inherits the change.

Override them in the scope you are theming. :root and .theme-light share one declaration block, while .theme-dark needs its own, because each theme redeclares the palette rather than inheriting it.

Component tokens

Component tokens are the narrowest layer. Form controls read --r-form-* , cards read --r-card-* , buttons read --r-button-* , and src/sass/_component-var.scss declares them all.

Most of them are shared by both themes and point at a semantic token, which is why a surface change reaches a component without editing it. A smaller group is declared twice, once for light and once for dark, for parts such as nav links, dropdown hover, tag, badge, and message surfaces.

CSS 
:root {
    --r-card-radius: var(--r-global-border-radius);
    --r-card-background: var(--r-surface);
    --r-card-header-footer-border: var(--r-border-subtle);
    --r-card-header-footer-color: var(--r-text-subtle);

    --r-form-input-background-color: var(--r-surface-raised);
    --r-form-input-border-color: var(--r-border-control);
    --r-form-input-radius: var(--r-global-border-radius);
    --r-form-input-color: var(--r-text-control);
    --r-form-input-focus-border-color: var(--r-accent);
}

Reach for this layer when a change should stop at one component. Cards take radius, background, and header and footer treatment from four tokens, and a form input takes its surface, border, radius, text, and focus color from its own set.

Dark mode toggle

roolith ships no JavaScript, so a toggle is a class flip on <html> . Set exactly one explicit class: the automatic media query only steps aside for .theme-light , and leaving both classes off means the operating system decides on every visit.

Reading the stored choice in <head> avoids a flash of the wrong mode, and toggling both classes keeps a stale value from winning on the next page load.

HTML 
<script>
    const root = document.documentElement;
    const stored = localStorage.getItem('theme');

    if (stored === 'dark' || stored === 'light') {
        root.classList.add(stored === 'dark' ? 'theme-dark' : 'theme-light');
    }

    function applyTheme(theme) {
        root.classList.toggle('theme-dark', theme === 'dark');
        root.classList.toggle('theme-light', theme === 'light');
        localStorage.setItem('theme', theme);
    }

    document.addEventListener('DOMContentLoaded', function () {
        document.querySelector('[data-theme-toggle]').addEventListener('click', function () {
            applyTheme(root.classList.contains('theme-dark') ? 'light' : 'dark');
        });
    });
</script>

The button in the demo above uses the docs site's own toggle hook, which flips the same two classes. Because each theme sets color-scheme , scrollbars and native form controls follow the class without extra CSS.

Inspecting the tokens

The generated stylesheet lists each token with its value and the scope that declares it, which makes it the fastest way to find a name without reading the Sass. npm run css-vars writes the theme tokens; npm run css-vars:all adds every custom property the framework sets, including component scoped ones such as --grid-span .

Both scripts write dist/roolith-variables.css . Pass --out to write somewhere else, and regenerate after a build because the build empties dist/ .

Shell 
npm run css-vars
npm run css-vars:all
node scripts/generate-css-variables.mjs --out tokens.css
