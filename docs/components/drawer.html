Drawer

A drawer slides a panel in from the right over a full-screen scrim. The styles are a container, the panel, and an .open state; everything else is optional header, body, and footer markup.

class: .drawer-container - defined in modules/_drawer.scss

Basic usage

The trigger is a normal button. Opening the drawer means adding .open to .drawer-container, which switches it from display: none to display: block and lets the panel run its fade-in animation. The button below is wired with the documentation hooks, so it works on this page.

The demo drawer lives at the end of this page, outside the demo box, because a fixed container cannot be previewed inline. Use the button to open it and the close button, the backdrop, or Escape to dismiss it.

HTML 
<button type="button" class="button button-primary" data-doc-drawer="#drawer-release-notes">
    Open drawer
</button>

<div class="drawer-container" id="drawer-release-notes">
    <div class="drawer" role="dialog" aria-modal="true" aria-labelledby="drawer-release-title">
        <div class="drawer-header" id="drawer-release-title">
            Release notes
            <span class="drawer-sub-header">Version 4.0.0 - 12 March 2025</span>
            <button type="button" class="drawer-close" data-doc-drawer-close aria-label="Close drawer">
                <svg viewBox="0 0 24 24" width="18" height="18" fill="none" stroke="currentColor" stroke-width="1.5" aria-hidden="true" focusable="false">
                    <path d="M6 6l12 12M18 6L6 18" stroke-linecap="round" />
                </svg>
            </button>
        </div>
        <div class="drawer-body">
            <p>
                The token layer moved into <code>_component-var.scss</code> and every component now reads its
                values from a custom property, so a theme can override one variable instead of a rule.
            </p>
            <p>
                Two components changed shape: the badge keeps its fixed 5px radius and uppercase label, and only the
                outline message variants draw a border.
                Both are listed in the upgrade guide.
            </p>
        </div>
        <div class="drawer-footer">
            <button type="button" class="button button-outline" data-doc-drawer-close>Cancel</button>
            <button type="button" class="button button-primary" data-doc-drawer-close>Save changes</button>
        </div>
    </div>
</div>

Mark any element inside the container with data-doc-drawer-close to make it close the drawer. The framework itself has no hooks, so pick your own attributes and keep them consistent.

Layout and backdrop

.drawer-container is fixed to the viewport at full size with a z-index of 9999 and a semi-transparent background token. It also carries the base padding, so the panel never touches the screen edge.

.drawer is absolutely positioned inside that padded area, anchored to the top and right with half the content spacing as an inset. It is full width up to a 600px cap, scrolls its own overflow, and runs the fadeInRight animation on open.

--r-drawer-content-spacing drives the container padding, the panel inset, the header and footer gaps, and the body height. Raise it once and the whole panel keeps its proportions. The body height is the panel height minus twice the spacing and a fixed 95px reserved for the header and footer, so keep those two slots close to their default height if you change their contents.

Place the container at the end of body rather than inside a card or a layout column. It is fixed, so its position in the flow does not matter visually, but keeping it last avoids stacking-context surprises with transformed or filtered ancestors.

JavaScript

roolith css ships no JavaScript. The snippet below is documentation only and is the behavior this page uses: the trigger opens the container, the close button and the backdrop close it, and Escape closes it while returning focus to the trigger.

JavaScript 
const trigger = document.querySelector('[data-doc-drawer]');
const container = document.querySelector('#drawer-release-notes');

/**
 * Show the drawer container.
 * @returns {void}
 */
function openDrawer() {
    container.classList.add('open');
}

/**
 * Hide the drawer container and return focus to the trigger.
 * @returns {void}
 */
function closeDrawer() {
    container.classList.remove('open');
    trigger.focus();
}

trigger.addEventListener('click', openDrawer);

container.addEventListener('click', (event) => {
    if (event.target.closest('.drawer-close, [data-doc-drawer-close]')) {
        closeDrawer();
        return;
    }

    if (!event.target.closest('.drawer')) {
        closeDrawer();
    }
});

document.addEventListener('keydown', (event) => {
    if (event.key === 'Escape' && container.classList.contains('open')) {
        closeDrawer();
    }
});

Only one drawer should be open at a time, and a drawer that opens another surface, such as a modal, should handle Escape in the right order so the topmost layer closes first. The docs script keeps a single open drawer for exactly that reason.

Accessibility

The framework ships the visual layer only, so the dialog semantics and focus behavior are yours to add. The list below is the minimum for a usable drawer.

  • Put role="dialog" and aria-modal="true" on .drawer, and point aria-labelledby at the id of .drawer-header so the panel has a name.
  • Move focus into the drawer when it opens. Focus the panel itself with tabindex="-1" or the first control, then keep Tab and Shift + Tab inside the drawer until it closes.
  • Return focus to the trigger on close. Without that, keyboard users land back at the top of the document.
  • Escape must close the drawer. Handle it at the document level while the drawer is open and ignore it when a nested surface is on top.
  • The closed state is display: none through the framework, so a closed drawer is already out of the tab order and the accessibility tree. Do not replace it with opacity or transform hiding that leaves it focusable.
  • Give the close button an aria-label when it holds an icon only, set type="button" so it cannot submit a form, and do not rely on the backdrop click for closing, since it is not a keyboard target.
  • Stop the page behind from scrolling while the drawer is open. The framework scrolls .drawer-body only and does not lock the document.

Class reference

Colors, spacing, radius, and the shadow come from the --r-drawer-* tokens, so a dark theme inherits the same structure with different values.

Class Applies Notes
.drawer-container Root Fixed full-screen scrim at z-index: 9999, hidden until it gains .open.
.open State on the container Switches the container to display: block.
.drawer Panel Right-anchored, 600px max width, radius, shadow, own scrolling, and the fadeInRight animation.
.drawer-header Header 18px title with 15px of bottom margin. Position the close button against it.
.drawer-sub-header Header subtitle Block level 14px dimmed line with 8px of top margin.
.drawer-body Body Scrollable area sized from the panel height minus the spacing and a 95px reserve.
.drawer-footer Footer Top border, 10px gap, and right-aligned actions laid out in a row.
.drawer-close Close button Pinned to the top right with 15px by 17px padding and a hover opacity change.
