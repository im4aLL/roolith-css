Tooltip

A tooltip adds one short line of context to something already on the page. roolith css offers two shapes: a data-tooltip attribute that draws its own text through a pseudo-element, and a .tooltip wrapper around a .tooltip-content element that can hold markup. Both open on hover and both need no JavaScript.

class: .tooltip - defined in modules/_tooltip.scss

Basic usage

data-tooltip is the shortest path. Put the text in the attribute and the module renders it in an ::after box above the element, centered on it, with the inverted surface from --r-tooltip-bg-color and the 12px type of the module.

The rule also sets position: relative, display: inline-block, and a pointer cursor on the element, so it works on a button, a link, or a plain span without extra markup.

Last sync
HTML 
<button type="button" class="button" data-tooltip="Rebuilds the cache for this environment.">Rebuild cache</button>

<span data-tooltip="Refreshed 2 minutes ago">Last sync</span>

The text from data-tooltip is drawn by a pseudo-element, so it is plain text only. For a heading, a paragraph, or a button inside the panel, use the wrapper below.

Tooltip wrapper

.tooltip is an inline-block wrapper with a dotted bottom border in --r-tooltip-border-color, which is the usual cue for an abbreviation or a term that needs a definition. The hover rule lives on the wrapper, so anything inside it keeps the tooltip open.

.tooltip-content is the panel. It uses the same surface, padding, radius, and 12px type as the attribute version, sits 5px above the wrapper, and is centered with a 50% left offset and translate.

The build runs in a sandbox No network access. with a read only copy of the production database.

HTML 
<p>
    The build runs in a
    <span class="tooltip">
        sandbox
        <span class="tooltip-content">No network access.</span>
    </span>
    with a read only copy of the production database.
</p>

The wrapper needs an inline context: it is display: inline-block, so using it as a block element centers itself under nothing. Wrap it in a paragraph or a line of text.

Positions

Without a modifier the panel sits above the wrapper and draws no arrow. .tooltip-up keeps that placement and adds a down pointing arrow at the bottom of the panel, which is the variant to use when you want the callout to read as a speech bubble.

.tooltip-bottom moves the panel 6px below the wrapper with an up pointing arrow. .tooltip-left and .tooltip-right place the panel beside the wrapper, vertically centered with a translate, and pull it 6px to 7px away so the arrow sits in the gap. Each direction prints its arrow with the shared triangle mixin in --r-tooltip-bg-color.

Up Panel above the trigger. Bottom Panel below the trigger. Left Panel to the left. Right Panel to the right.
HTML 
<span class="tooltip tooltip-up">
    Up
    <span class="tooltip-content">Panel above the trigger.</span>
</span>

<span class="tooltip tooltip-bottom">
    Bottom
    <span class="tooltip-content">Panel below the trigger.</span>
</span>

<span class="tooltip tooltip-left">
    Left
    <span class="tooltip-content">Panel to the left.</span>
</span>

<span class="tooltip tooltip-right">
    Right
    <span class="tooltip-content">Panel to the right.</span>
</span>

There is no collision handling. A left tooltip near the viewport edge, or a right tooltip near the right edge, is cut off. Pick the direction from the space around the trigger, not from the look you prefer.

Hover behavior

The reveal is two lines of CSS: .tooltip:hover .tooltip-content, and the matching ::after rule for the attribute version. Nothing is measured, positioned, or recalculated, so no script runs and no observer watches the page.

Both surfaces animate opacity and visibility with --r-tooltip-transition-duration (150ms) and --r-tooltip-transition-delay (250ms). The delay is what stops a tooltip from flashing as the pointer crosses a toolbar.

The panel stays hidden with opacity: 0 and visibility: hidden rather than display: none, so the transition can run in both directions. The panel is absolutely positioned, so the box it keeps does not push the surrounding text.

Lower the delay when the tooltip is the only way to read a value, and raise it when it is a hint on an otherwise self explaining control.

Large content

.tooltip-large drops white-space: nowrap, fixes the panel at 250px, and uses --r-tooltip-padding-large, which is 15px on every side. It is the only variant that can hold a paragraph.

Inside the panel, .tooltip-content-hl is the heading: 14px at the bold weight with 5px of bottom padding. .tooltip-content-button is a full width call to action with a 10px top margin, meant for a .button with button-small.

Retention policy Retention policy Logs are kept for 30 days in the hot tier, then moved to cold storage for a year.
HTML 
<span class="tooltip tooltip-large">
    Retention policy
    <span class="tooltip-content">
        <span class="tooltip-content-hl">Retention policy</span>
        Logs are kept for 30 days in the hot tier, then moved to cold storage for a year.
    </span>
</span>

A 250px panel with a paragraph is already a small card. Two or three lines is the limit before a popover is the better tool, and anything clickable inside a hover panel has the gap problem described in the accessibility notes.

Active state

.tooltip-active forces the panel visible with opacity: 1 and visibility: visible, regardless of hover. Add it when you toggle a tooltip from a click, when a form field needs a persistent hint, or when the panel contains a control that must be reachable without holding the pointer still.

The class goes on the .tooltip wrapper, and it lasts as long as the class does, so your script owns the timing.

Export settings Export settings The export runs in the background and emails a signed link when the file is ready. Open export queue
HTML 
<span class="tooltip tooltip-bottom tooltip-large tooltip-active">
    Export settings
    <span class="tooltip-content">
        <span class="tooltip-content-hl">Export settings</span>
        The export runs in the background and emails a signed link when the file is ready.
        <a class="button button-small button-primary tooltip-content-button" href="#">Open export queue</a>
    </span>
</span>

Once the panel holds a link or a button, use the popover component instead. It already handles outside clicks, Escape, and focus, and a hover tooltip does not.

Accessibility

Hover is a pointer only input. The module has no :focus, :focus-within, or touch fallback, so treat the tooltip as an enhancement and never as the only place a value or an instruction exists.

  • Do not hide required information in a tooltip. Repeat anything essential in visible text, a helper line under the field, or an inline message.
  • Link the panel to its trigger with aria-describedby when the text matters, because a pseudo-element from data-tooltip is not a reliable description for assistive technology.
  • Keyboard users cannot open a hover tooltip. Add your own :focus-visible rule that reveals .tooltip-content, or use .tooltip-active on focus, or switch to a popover when the content has to be reachable.
  • Touch devices have no hover, and some browsers fire it once on tap and never again. Assume the panel is unreachable on a phone.
  • Keep the panel non interactive. Crossing the 5px gap between the trigger and the panel drops :hover, so a link inside it is hard to click and impossible to tab to reliably.
  • The module sets cursor: pointer on every .tooltip and [data-tooltip] element. If the element does something on click, make it a real <button> or <a> rather than styling a span to look like one.
  • white-space: nowrap is the default, so long text runs off the edge. Use .tooltip-large for anything longer than a few words, and keep the first line short.
  • Reduced motion is handled globally: the base reset collapses transition durations and delays when the user asks for it, so the panel appears without the fade.

Class reference

Direction and size classes go on the .tooltip wrapper. The .tooltip-content element is always a child of that wrapper, never a sibling.

Class Applies Notes
.tooltip Wrapper Inline-block, relative, pointer cursor, and a dotted bottom border in --r-tooltip-border-color. Owns the hover rule.
.tooltip-content Panel Absolutely positioned above the wrapper, hidden by opacity and visibility, with --r-tooltip-padding, the token radius, and 12px type over 18px.
[data-tooltip] Any element Attribute version. Draws attr(data-tooltip) in an ::after box above the element and sets a relative inline-block box.
.tooltip-up Direction Keeps the panel above and adds a down pointing arrow at its bottom edge.
.tooltip-bottom Direction Panel 6px below the wrapper with an up pointing arrow on top.
.tooltip-left Direction Panel to the left, vertically centered, 7px away, with a right pointing arrow.
.tooltip-right Direction Panel to the right, vertically centered, 6px away, with a left pointing arrow.
.tooltip-large Size 250px wide panel that wraps instead of staying on one line, padded by --r-tooltip-padding-large.
.tooltip-content-hl Content Panel heading at 14px and the bold weight token, with 5px of bottom padding.
.tooltip-content-button Content Full width action with a 10px top margin. Pair it with .button.button-small.
.tooltip-active State Forces the panel visible. Put it on the wrapper and remove it from your own script.
