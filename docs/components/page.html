Page

Page is a shell for screens that hold one message: an error, a confirmation, or an empty state. It centers a content block in the viewport by default, and page-normal turns it back into normal flow so it can sit inside a layout column.

class: .page - defined in modules/_page.scss

Basic usage

.page is a flex container that centers its single child both ways. Inside it, .page-content holds the four slots: an optional .page-icon , a .page-header for the title, a .page-body for the explanation, and a .page-footer for a note or a link.

.page-normal goes on the same element as .page . It sets height: auto and display: block , and its content block switches to left aligned text with 60px of top padding. Use it whenever the shell is not the whole screen, for example inside a dashboard column or a card area.

.page-icon only sets a 72px font size for an icon font glyph. An inline SVG needs its own width and height, as above. Add a .color-{name} utility to the icon or the header to tint either one without new CSS.

Full-height shell

Without .page-normal the shell declares height: 100% and then height: 100vh and centers the content block, which is the shape you want for a standalone route such as a 404 or an auth result. Place it directly under body or inside the main region, not inside a card that already has its own padding.

The demo pins a 300px height on the shell so it fits on this page. In production the class does not need it: leave the height alone and let 100vh do the work.

A 404 screen

A not-found route is the typical use: one heading, one sentence of explanation, and one way out. Use .page-normal when the shell renders inside an existing layout, and keep the heading level at h1 on a standalone route because it is then the only heading on the screen. The live demo uses h2 because it sits inside this page, which already has an h1 .

.page-footer adds 100px of top padding, then drops to 80% font size and 0.6 opacity, so it reads as a footnote rather than a second message. If you need an action, put it at the end of .page-body where the 14px body line height keeps it close to the explanation.

The same shell carries an empty state: swap the icon for an inbox or folder glyph, keep the heading action oriented, and put the primary action in the body.

Accessibility

The shell only draws the surface. The landmark, the heading, and the focus behavior belong to the page that renders it.

  • Render the shell inside a real main landmark, and keep one h1 on the screen. Put .page-header on that heading rather than on a second title.
  • Announce a 404 or a status screen in the document title and in the heading text, so the message does not depend on the icon or the color.
  • On a client-side route change, move focus to the heading. A route that only swaps content leaves a keyboard and screen reader user at the top of the previous page.
  • Hide decorative icons from assistive technology with aria-hidden="true" on the SVG, and give an icon that carries meaning a text alternative when no visible text explains it.
  • Keep the visual shell presentational. .page adds no role and no label, so the surrounding layout has to supply the landmark and the heading level.

Class reference

The shell classes are structural and read no component tokens beyond the palette utilities used for color. Spacing comes from fixed rem values in the module.

Class Applies Notes
.page Base Full viewport height as a flex container, centered on both axes.
.page-normal Variant On the same element as .page . Height auto and block display for use inside a layout.
.page-content Child Centered text by default; under .page-normal it gets 60px of top padding and left aligned text.
.page-icon Slot Sets a 72px font size for an icon glyph. Inline SVG needs its own size.
.page-header Slot Title block with 10px top and 20px bottom padding.
.page-body Slot 14px text over a 22px line height.
.page-footer Slot 100px top padding, 80% font size, and 0.6 opacity.
