Toast notification

A toast is a short confirmation that arrives after the page has already moved on. .toast-notification is only the positioning wrapper: it pins itself to a corner of the viewport, and the .message you put inside it supplies the surface, the padding, and the color.

class: .toast-notification - defined in modules/_toast-notification.scss
This module styles the wrapper only. It has no visible surface of its own, so an empty .toast-notification renders as nothing at all. The surface, radius, and spacing all come from the message component inside it.

Basic usage

The wrapper is fixed, capped at --r-toast-notification-width, and placed 30px from the right edge and 20px from the top, which makes top right the default position.

Inside it goes a .message with the text you want to announce. The buttons below carry the documentation hook, which appends exactly this markup to the body and removes it again after a few seconds. Click one and look at the top right corner.

HTML 
<div class="toast-notification">
    <div class="message message-success">Saved successfully.</div>
</div>

The trigger attribute in the demo is a documentation hook, not part of the framework. A real page appends the wrapper with its own code, covered in the JavaScript section below.

Because the wrapper is fixed, it leaves the document flow completely. The page underneath does not reflow when a toast appears, and the toast is not clipped by any card, drawer, or scroll container.

Positions

Three modifiers move the wrapper away from the default top right corner. Add the class to the wrapper, not to the message inside it.

.bottom centers the wrapper horizontally 0px from the bottom edge and also centers its text. .left sits 30px from the left edge and 20px from the bottom, and .top sits 30px from the left edge and 20px from the top.

HTML 
<div class="toast-notification bottom">
    <div class="message message-success">Report exported to CSV.</div>
</div>

<div class="toast-notification left">
    <div class="message message-success">Invite sent to 3 people.</div>
</div>

<div class="toast-notification top">
    <div class="message message-success">Filters applied.</div>
</div>

The documentation hook accepts bottom, left, and top through data-doc-toast-position. Pick one corner per app and stay there, so a reader learns where to look after the first toast.

Placement and stacking

The default corner is right 30px and top 20px, with a z-index of 10 on the wrapper. .top keeps the 20px top offset and moves to the left edge, while .left clears the top offset and drops to 20px from the bottom.

.bottom is the different one: it clears the top offset, anchors to 0px from the bottom, centers itself with a 50% right offset and a 50% translate, centers the text, and adds 20px of padding so the message never touches the screen edge.

The wrapper is capped by --r-toast-notification-width, which is 25rem by default. A long message wraps inside that cap rather than stretching across the viewport.

That z-index of 10 is low in practice: the sticky header in the layout shell uses 1000, and any ancestor that opens a stacking context can place the wrapper beneath other chrome. A toast can therefore render under an application header. Raise z-index on .toast-notification in your own stylesheet when that happens. This docs page does exactly that, with a higher z-index on the demo wrapper so it clears the docs header.

Every wrapper at the same corner lands on the same coordinates, so two live toasts overlap. Either remove the previous toast before showing a new one, or manage a small queue and stack them yourself with your own offsets. The module ships no queue.

Surfaces

The message is a component of its own, and the toast inherits whatever it brings. Without a color class it uses --r-message-background and the default text color.

A color class mixes 10% of the palette color into --r-surface-raised for the background and takes the label from the text safe palette value. That is the tint that tells a reader at a glance whether the toast is a confirmation, a warning, or a failure.

Settings saved.
Deployment finished.
Rate limit is at 80%.
Upload failed. Try again.
HTML 
<div class="message">Settings saved.</div>
<div class="message message-success">Deployment finished.</div>
<div class="message message-warning">Rate limit is at 80%.</div>
<div class="message message-danger">Upload failed. Try again.</div>

A message can also carry a .message-close button, but removing that button's parent leaves an empty fixed wrapper behind. When a toast has a close control, remove the .toast-notification element itself, not just the message.

JavaScript

roolith css ships no JavaScript. The snippet below is documentation only and is the behavior this page uses: build the wrapper, put a message inside it, append it to the body, and remove it on a timer.

JavaScript 
const TOAST_DURATION = 3500;

/**
 * Append a toast notification to the body and remove it after a short delay.
 * @param {string} text - Message text to announce.
 * @param {string} [position] - One of bottom, left, or top. Omit for top right.
 * @returns {void}
 */
function showToast(text, position) {
    const toast = document.createElement('div');
    toast.className = 'toast-notification';

    if (position === 'bottom' || position === 'left' || position === 'top') {
        toast.classList.add(position);
    }

    const message = document.createElement('div');
    message.className = 'message message-success';
    message.setAttribute('role', 'status');
    message.textContent = text;

    toast.appendChild(message);
    document.body.appendChild(toast);

    setTimeout(() => toast.remove(), TOAST_DURATION);
}

const trigger = document.querySelector('[data-toast-trigger]');

trigger.addEventListener('click', () => {
    showToast('Saved successfully.', 'bottom');
});

Use textContent rather than innerHTML for the message body. The text usually comes from user data, and the message is in the live region that screen readers read out.

Keep the timer tied to the toast element, not to a global, so two quick actions can each clear their own toast without cancelling the other.

Accessibility

A toast is a status update, not a dialog. It should never take focus and it should never be the only place a user can read something important.

  • Put role="status" on the message so it is announced politely, or role="alert" for a failure that needs immediate attention. Both imply a live region, so you do not need aria-live as well.
  • Insert the message with its text already in place, which is what this page does and what current screen readers announce. If you need a stronger guarantee, keep one empty live region in the layout and write each toast text into it instead of moving the region itself.
  • Do not move focus into the toast, and do not remove focus from the control that triggered it. A pointer switch to a fixed corner breaks keyboard work.
  • A toast that disappears on a timer can cut a slow reader off. Keep the text to one sentence, repeat lasting state somewhere in the page, and never put an error's only explanation in a toast.
  • If a toast needs a close control, use a real <button> with an aria-label, keep it focusable, and do not auto dismiss while it is focused.
  • The message tint is decoration. Write the state in the words, such as Upload failed, and let the color support it.
  • Keep the fixed corner clear of other fixed chrome. At high zoom the wrapper takes a large part of the viewport, so let the message wrap instead of widening it.

Class reference

The position classes go on .toast-notification. The message classes belong to the message component and are listed here because a toast needs one.

Class Applies Notes
.toast-notification Base Fixed wrapper, right 30px and top 20px, capped by --r-toast-notification-width. No surface of its own.
.bottom Position Anchored to the bottom edge and centered horizontally with a 50% right offset plus translate. Centers text and adds 20px of padding.
.left Position Bottom 20px and left 30px. Clears the default right and top offsets.
.top Position Top 20px and left 30px. Clears the default right offset.
.message Content 14px text with 17px by 30px by 17px by 20px padding, the token radius, and --r-message-background. Supplies the visible surface.
.message-success Content Any palette name except white: primary, secondary, tertiary, info, success, warning, danger, link, dark, black, light.
.message-close Content Absolutely positioned close control at the top right of the message. Removing it does not remove the toast wrapper.
