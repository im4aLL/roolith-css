Datepicker

roolith css ships no datepicker widget. It styles the native date and time inputs, and it supplies a thin skin for the panel the js-datepicker library renders inside .form-datepicker-js. The rest of the field system lives on the Form and Form extended pages.

class: .form-datepicker and .form-datepicker-js - defined in modules/_form-extended.scss and modules/_datepicker.scss
All behavior comes from the browser for native inputs, and from the third-party library for the JavaScript panel. Nothing is faked on this page.

Native date input

Wrap an <input type="date"> in .form-field.form-datepicker and give it .form-input for the shared field shape. The wrapper drops the native appearance, fixes the input height at 39px, and hides the ::-webkit-calendar-picker-indicator so the icon is consistent across browsers.

A calendar icon is drawn as an inline SVG in the wrapper's ::after pseudo-element and set to pointer-events: none, so clicks pass through to the input. No icon font and no extra element are needed.

HTML 
<div class="form-field form-datepicker">
    <label for="start-date" class="form-label">Start date</label>
    <input type="date" class="form-input" id="start-date" name="start-date" />
</div>

The calendar picker itself is opened by the browser. The framework only controls the field, the icon, and the focus and hover states inherited from .form-input.

Sizes

Add .small or .large to the .form-field wrapper. The input height moves to 27px or 44px and the icon is repositioned and resized to match.

HTML 
<div class="form-field small form-datepicker">
    <label for="date-small" class="form-label">Small</label>
    <input type="date" class="form-input" id="date-small" name="date-small" />
</div>
<div class="form-field form-datepicker">
    <label for="date-default" class="form-label">Default</label>
    <input type="date" class="form-input" id="date-default" name="date-default" />
</div>
<div class="form-field large form-datepicker">
    <label for="date-large" class="form-label">Large</label>
    <input type="date" class="form-input" id="date-large" name="date-large" />
</div>

Date and time types

The wrapper is not tied to a single input type. Any native date or time type that renders a picker works: datetime-local, month, week, and time.

Use .form-timepicker instead of .form-datepicker for time fields, because it swaps the calendar icon for a clock icon.

HTML 
<div class="form-field form-datepicker">
    <label for="when" class="form-label">Date and time</label>
    <input type="datetime-local" class="form-input" id="when" name="when" />
</div>
<div class="form-field form-datepicker">
    <label for="month" class="form-label">Month</label>
    <input type="month" class="form-input" id="month" name="month" />
</div>
<div class="form-field form-datepicker">
    <label for="week" class="form-label">Week</label>
    <input type="week" class="form-input" id="week" name="week" />
</div>
<div class="form-field form-timepicker">
    <label for="time" class="form-label">Time</label>
    <input type="time" class="form-input" id="time" name="time" min="09:00" max="17:00" step="900" />
</div>

Third-party datepicker

For a text input with a calendar panel, use the js-datepicker library and add .form-datepicker-js next to .form-datepicker. The class does two things: it reserves 32px of right padding on the input and scopes every .qs- override to that wrapper.

Load the library stylesheet, then its script, then initialize it against the inputs inside the wrapper. The overrides only apply when the generated panel ends up inside .form-datepicker-js, which happens when the wrapper is the input's parent; if your version appends the panel to the body, pass the wrapper as the panel parent.

Click the field to open the calendar. The library builds the panel at runtime and the framework restyles it, so this demo behaves exactly like the snippet below.

HTML 
<link rel="stylesheet" href="https://unpkg.com/js-datepicker/dist/datepicker.min.css" />

<div class="form-field form-datepicker form-datepicker-js">
    <label for="start-date" class="form-label">Start date</label>
    <input type="text" class="form-input" id="start-date" name="start-date" autocomplete="off" />
</div>

<script src="https://unpkg.com/js-datepicker"></script>
<script>
    datepicker('.form-datepicker-js .form-input');
</script>

The library owns the date math, keyboard handling, and the markup it generates. The framework only restyles that markup, so upgrading either side is independent of the other.

Styling the library panel

The overrides target the classes js-datepicker renders. The snippet below is the markup that library produces, reduced to one week, so you can see which parts the framework touches. The panel is built at runtime, so the snippet is static while the demo above shows the styled result once you open it.

HTML 
<div class="qs-datepicker-container">
    <div class="qs-datepicker">
        <div class="qs-controls">
            <div class="qs-arrow qs-left"></div>
            <div class="qs-month-year">
                <span class="qs-month">March</span>
                <span class="qs-year">2025</span>
            </div>
            <div class="qs-arrow qs-right"></div>
        </div>
        <div class="qs-squares">
            <div class="qs-square qs-day">Su</div>
            <div class="qs-square qs-day">Mo</div>
            <div class="qs-square qs-day">Tu</div>
            <div class="qs-square qs-day">We</div>
            <div class="qs-square qs-day">Th</div>
            <div class="qs-square qs-day">Fr</div>
            <div class="qs-square qs-day">Sa</div>
            <div class="qs-square qs-empty"></div>
            <div class="qs-square qs-empty"></div>
            <div class="qs-square"><span class="qs-num">1</span></div>
            <div class="qs-square"><span class="qs-num">2</span></div>
            <div class="qs-square qs-current"><span class="qs-num">3</span></div>
            <div class="qs-square qs-active"><span class="qs-num">4</span></div>
            <div class="qs-square qs-disabled"><span class="qs-num">5</span></div>
        </div>
    </div>
</div>

The container carries the surface, border, radius, and top margin. The controls row gets its own background, the two .qs-arrow elements become 25px by 30px hit areas with a hover background, and the arrows themselves are recolored through their ::after border. Every cell is 28px tall and the rows are separated by the row-gap token.

The hover rule skips .qs-empty, .qs-disabled, .qs-day, and .qs-active, so weekday labels, padding cells, and unselectable days never react to the pointer. The selected day is painted by .qs-active with the active background and text tokens.

Accessibility

Native inputs are accessible as long as they are labeled. The library panel brings its own keyboard model, and the framework does not change it, so test it rather than assuming.

  • Always pair the input with a <label for> or an aria-label. A placeholder disappears as soon as the user types, and it does not name the field.
  • Keep the name attribute so the submitted value is identifiable, and set autocomplete="off" on the text input if the browser's own suggestion panel competes with the library panel.
  • The arrow keys, Enter, and Escape belong to the library. Confirm they work with the keyboard only, and that focus returns to the input when the panel closes.
  • The selected day is communicated by background color alone. Check the contrast of the active background and text token pair in both light and dark mode.
  • .qs-empty and .qs-disabled cells are visual only. If a range of dates is unavailable, state that in text next to the field as well.
  • Do not remove the focus style from the input. The framework outlines .form-input on :focus-visible and that is the only cue that ties the field to the open panel.

Class reference

The first group is framework markup. The second group is generated by js-datepicker and only styled inside .form-datepicker-js.

Class Applies Notes
.form-field Wrapper Relative positioning for the icon. Also accepts .small and .large.
.form-datepicker Wrapper modifier Resets the native appearance, sets a 39px input height, and draws the calendar icon.
.form-timepicker Wrapper modifier Same treatment as the date wrapper, with a clock icon.
.form-datepicker-js Wrapper modifier 32px of right input padding and the scope for every qs override below.
.qs-datepicker-container Library root Font, size, color, border, radius, top margin, and background.
.qs-controls Library header row Background color only.
.qs-arrow Library nav arrows 25px by 30px with a hover background; the glyph is recolored through ::after.
.qs-month-year Library label Font weight from the strong weight token.
.qs-squares Library grid Row gap only. The columns come from the library stylesheet.
.qs-square Library cell 28px tile height. Hover skips empty, disabled, day, and active cells.
.qs-day Library weekday label Font weight only.
.qs-current Library today cell Font weight only.
.qs-active Library selected cell Active background and text color tokens.
.qs-empty Library state Not a framework style. It is js-datepicker's marker for a padding cell and appears only inside the :not(.qs-empty) guard on the hover rule. Same for .qs-disabled.
