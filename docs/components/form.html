Form

Form controls share one wrapper: .form-field holds the label, the control, and the helper text, and its state classes recolor all three at once. Everything is applied to native elements, so validation, keyboard behavior, and submission stay with the browser.

class: .form-field - defined in modules/_form.scss
Colors, borders, radius, and spacing come from the --r-form-* token layer. Override --r-form-input-border-color, --r-form-input-radius, or --r-form-error-color once and every field on the page follows, in both themes.

Basic usage

.form-field is the layout unit. It is relatively positioned so icons and toggles can be anchored to it, and inside a .form wrapper it adds 20px of bottom margin between fields.

.form-label is a block level 14px label on an 18px line with 8px of bottom padding, so it sits above the control without a wrapper. The control carries .form-input: full width, a 1px border, the token radius, and 10px by 12px of padding. Hover raises the border to the link color and focus raises it to the accent.

Helper text is a <small class="form-text"> below the control: 11px, 8px of top padding, and the muted helper color.

Used in the repository URL and the release notes.
HTML 
<div class="form-field">
    <label class="form-label" for="project-name">Project name</label>
    <input class="form-input" type="text" id="project-name" name="project-name" placeholder="roolith-css" aria-describedby="project-name-help" />
    <small class="form-text" id="project-name-help">Used in the repository URL and the release notes.</small>
</div>

Wrap a group of fields in .form to get the 20px rhythm between them. The class adds no other styling, so it is safe on a <form>, a <div>, or a section of a larger layout.

Validation states

Put error, success, or warning on .form-field. The state recolors the label, the control border, and the helper text from one class, using --r-form-error-color, --r-form-success-color, and --r-form-warning-color.

The state is visual only. Pair it with aria-invalid="true" on the control and an error message that is referenced by aria-describedby, so the message reaches keyboard and screen reader users too.

Enter a complete address, for example ada@example.com.
This slug is available.
Your plan includes 50 seats.
HTML 
<div class="form-field error">
    <label class="form-label" for="email">Email address</label>
    <input class="form-input" type="email" id="email" name="email" value="ada@" aria-invalid="true" aria-describedby="email-help" />
    <small class="form-text" id="email-help">Enter a complete address, for example ada@example.com.</small>
</div>

<div class="form-field success">
    <label class="form-label" for="slug">Workspace slug</label>
    <input class="form-input" type="text" id="slug" name="slug" value="acme-platform" aria-describedby="slug-help" />
    <small class="form-text" id="slug-help">This slug is available.</small>
</div>

<div class="form-field warning">
    <label class="form-label" for="seats">Seats</label>
    <input class="form-input" type="number" id="seats" name="seats" value="48" aria-describedby="seats-help" />
    <small class="form-text" id="seats-help">Your plan includes 50 seats.</small>
</div>

Text and native inputs

.form-input is type agnostic: it styles the box, not the value, so email, tel, url, number, search, and the rest keep their native keyboards, constraints, and validation.

Pick the type that matches the data. type="email" gives a mobile keyboard with an at sign and a built-in format check, type="tel" gives a numeric keypad, and type="number" gives steppers plus min, max, and step. Date and time inputs have their own wrappers on the Form extended page.

HTML 
<div class="form-field">
    <label class="form-label" for="email">Email</label>
    <input class="form-input" type="email" id="email" name="email" placeholder="ada@example.com" autocomplete="email" />
</div>

<div class="form-field">
    <label class="form-label" for="phone">Phone</label>
    <input class="form-input" type="tel" id="phone" name="phone" placeholder="+1 555 019 2837" autocomplete="tel" />
</div>

<div class="form-field">
    <label class="form-label" for="website">Website</label>
    <input class="form-input" type="url" id="website" name="website" placeholder="https://example.com" />
</div>

<div class="form-field">
    <label class="form-label" for="seats">Seats</label>
    <input class="form-input" type="number" id="seats" name="seats" value="5" min="1" max="50" />
</div>

Select and textarea

.form-select shares the input skin and adds its own arrow: the native appearance is removed and a chevron SVG is drawn at 10px from the right edge, with 32px of right padding to clear it. The dark theme swaps the chevron for a lighter one, and [multiple] drops the arrow because a list box has nothing to open.

.form-textarea shares the same skin, keeps only vertical resizing, and starts at 137px tall.

Checkboxes and radios

Checkboxes are fully custom. .form-checkbox-label is a block label with 25px of left padding, and .form-check-input is an appearance-none 15px box placed at the left edge. When it is checked the fill turns accent and a check mark is drawn with a mask, so the mark follows the accent color in both themes. Add .is-indeterminate to a checkbox that represents a partially selected group.

Radios stay native. .form-radio-items is a flex row with a 10px gap and .form-radio-item is a label that centers the native radio with 5px between it and the text. Add vertical to the .form-field wrapper to stack the list with a 5px gap, and .is-multiline to an item with a long label so the radio aligns with the first line instead of the middle.

.form-radio only zeroes the native margin, so a radio outside .form-radio-item keeps the browser default. The checkbox class draws its own mark, which means a checkbox without .form-check-input keeps the native box and is still a valid form control.

File input

.form-file styles the one part of a file input that can be styled: the ::file-selector-button, which borrows the shared button base and the small button metrics. The filename area stays native, so the visible result is a small button next to the browser's own text.

PNG or JPEG, up to 2 MB.
HTML 
<div class="form-field">
    <label class="form-label" for="photo">Profile photo</label>
    <input class="form-file" type="file" id="photo" name="photo" accept="image/png, image/jpeg" aria-describedby="photo-help" />
    <small class="form-text" id="photo-help">PNG or JPEG, up to 2 MB.</small>
</div>

Do not add .form-input to the same element. The input class draws a full border and padding for a text field, which would frame the native file control twice.

Search field

.form-field-search is a positioned wrapper with no padding of its own. The input keeps .form-input and gains 34px of left padding for the icon, which is an ordinary .form-field-search-icon span placed at 12px from the left, 8px from the top, and painted in the placeholder color.

Add loading to the wrapper and include a .form-field-search-loading-icon element to show a 16px spinner pinned 12px from the right. The input also gains 34px of right padding while loading so text never runs under it.

The same wrapper accepts a suggestion list: add hint to it and a .form-field-search-hint element holding a list of links. The list is absolutely positioned under the field, capped at 300px with its own scroll area, and each link gets a hover surface. The hint is not shown on this page because it overlaps the code panel below the demo.

HTML 
<div class="form-field form-field-search">
    <span class="form-field-search-icon"><i class="icon icon-search"></i></span>
    <input class="form-input" type="search" name="query" placeholder="Search components" aria-label="Search components" />
</div>

<div class="form-field form-field-search loading">
    <span class="form-field-search-icon"><i class="icon icon-search"></i></span>
    <input class="form-input" type="search" name="filter" placeholder="Filter results" aria-label="Filter results" />
    <i class="form-field-search-loading-icon"></i>
</div>

The wrapper also scales: small moves the icon to 7px by 6px and narrows both paddings, and large grows the icon to 130% and moves it down to 10px. The loading spinner drops to 12px on the small variant.

Password field

.form-field-password is a grid whose input and .form-password-toggle button share one cell, placed below the label. The input gets 40px of right padding and the toggle is aligned to the end of that cell, so the button never covers the text.

The toggle itself is a transparent 18px button with no border, colored with the input text token, and it is the only part of the field that needs script. The framework positions the button; switching the input type is up to you.

HTML 
<div class="form-field form-field-password">
    <label class="form-label" for="password">Password</label>
    <input class="form-input" type="password" id="password" name="password" autocomplete="current-password" />
    <button class="form-password-toggle" type="button" aria-label="Show password" aria-pressed="false">
        <svg width="18" height="18" viewBox="0 0 24 24" fill="none" aria-hidden="true" focusable="false">
            <path d="M2 12s3.5-7 10-7 10 7 10 7-3.5 7-10 7-10-7-10-7Z" stroke="currentColor" stroke-width="1.5" stroke-linecap="round" stroke-linejoin="round" />
            <circle cx="12" cy="12" r="3" stroke="currentColor" stroke-width="1.5" />
        </svg>
    </button>
</div>

Keep the toggle a real <button type="button">, update aria-pressed and its label when the visibility changes, and leave autocomplete="current-password" in place. Hiding the value again should return focus to the input, not to the button, so typing can continue.

Sizes, primary, and disabled

Size classes go on the .form-field wrapper, not the control. small drops the label to 12px on a 16px line with 5px of bottom padding, sets 12px control text, and cuts the input padding to 5px by 7px. large raises the label to 16px on a 22px line, sets 16px control text, and pads the input 11px by 12px.

.form-primary is a wrapper that repaints every input, textarea, and select inside it: the fill comes from --r-form-primary-color and the border from --r-form-primary-border-color. Hover turns the border to the info color, and focus moves both the border and the fill to --r-form-primary-focus-color, which resolves to the normal input surface, so the field appears unfilled again while it has focus.

An input with the native readonly attribute gets the muted fill from --r-form-disable-input-color and keeps its resting border on hover and focus. The framework has no :disabled rule, so a native disabled input keeps browser styling; use it when the field must also be removed from submission and the tab order.

HTML 
<div class="form-field small">
    <label class="form-label" for="size-small">Small</label>
    <input class="form-input" type="text" id="size-small" name="small" placeholder="Dense toolbar" />
</div>

<div class="form-field">
    <label class="form-label" for="size-default">Default</label>
    <input class="form-input" type="text" id="size-default" name="default" placeholder="Standard field" />
</div>

<div class="form-field large">
    <label class="form-label" for="size-large">Large</label>
    <input class="form-input" type="text" id="size-large" name="large" placeholder="Prominent field" />
</div>

<div class="form-primary">
    <div class="form-field">
        <label class="form-label" for="primary">Primary fill</label>

.form-label.right right-aligns a label and adds 8px of top padding from the large breakpoint up, which is what an inline label and control row needs. Below that breakpoint the label returns to its normal block layout.

Complete form

A realistic form stacks the pieces: a text field, a typed field, a select, a textarea, a checkbox with its consent copy, and a bundle of actions. The .form wrapper supplies the spacing, and the fields keep their own helper text so the form can explain itself without a second column.

We send the invite link here.
HTML 
<form class="form" action="/workspaces" method="post">
    <div class="form-field">
        <label class="form-label" for="name">Full name</label>
        <input class="form-input" type="text" id="name" name="name" autocomplete="name" required />
    </div>

    <div class="form-field">
        <label class="form-label" for="email">Work email</label>
        <input class="form-input" type="email" id="email" name="email" placeholder="ada@example.com" autocomplete="email" required aria-describedby="email-help" />
        <small class="form-text" id="email-help">We send the invite link here.</small>
    </div>

    <div class="form-field">
        <label class="form-label" for="team">Team size</label>
        <select class="form-select" id="team" name="team">
            <option value="1-10">1 to 10 people</option>
            <option value="11-50">11 to 50 people</option>
            <option value="51-200">51 to 200 people</option>
        </select>
    </div>

    <div class="form-field">
        <label class="form-label" for="message">What are you building?</label>
        <textarea class="form-textarea" id="message" name="message" placeholder="A design system for three product teams."></textarea>
    </div>

    <div class="form-field">
        <label class="form-checkbox-label">
            <input class="form-check-input" type="checkbox" name="terms" required />
            I agree to the terms of service and the privacy policy.
        </label>
    </div>

    <div class="button-bundle">
        <button class="button button-outline" type="reset">Reset</button>
        <button class="button button-primary" type="submit">Create workspace</button>
    </div>
</form>

Accessibility

Every control needs a programmatic name, and the visual label is the cheapest way to give it one. The framework styles the label; the association is markup.

  • Give every input an id and point the <label for> at it. A label that wraps the input also works for checkbox and radio items, which is why those are built that way.
  • Do not use the placeholder as a label. It disappears on input, it is not reliably announced, and the helper text below is a description, not a name.
  • Mark required fields with the native required attribute. The browser blocks submission and announces the failed constraint, so a red asterisk alone is not a substitute. If you add one, put the meaning in text such as "all fields required".
  • Connect helper and error text with aria-describedby, and add aria-invalid="true" while a field is in the error state. Both point at the same .form-text element the state class colors.
  • Group radios and checkboxes that answer one question. A <fieldset> with a <legend> is the simplest option; a wrapper with role="radiogroup" and aria-labelledby pointing at a .form-label also works, and it avoids resetting the fieldset border.
  • Keep a visible focus indicator. The framework moves the border to the accent on focus; if you change that token, check the contrast against the surrounding surface.
  • For the search field, give the input an aria-label when there is no visible label, and announce result counts in a live region elsewhere on the page rather than relying on the spinner.
  • The password toggle needs a name, a pressed state, and a label that changes with the action, for example "Show password" and "Hide password".

Class reference

Most classes are modifiers on .form-field or on the control itself. Sizes and states belong to the wrapper so they can reach the label, the control, and the helper text with one class.
