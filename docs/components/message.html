Message

A message is an inline block for feedback that belongs to the page: the result of a form submit, a warning above a table, or a status line inside a card. The base class owns the padding, radius, and page flow, and a color class tints the surface from the palette.

class: .message - defined in modules/_message.scss
Every color class is generated from the palette loop in _message.scss , so overriding --r-color-success or --r-surface-raised repaints the whole family. The loop skips white , which means there is no .message-white .

Basic usage

.message is a block with 17px of top and bottom padding and 20px of left padding against 30px on the right, which reserves the corner for a close button. It carries 14px text on a 1.5 line height, the token radius, 10px of vertical margin, and its own background token, so a stack of messages reads as separate blocks without a wrapper.

Without a color class the surface is the neutral --r-message-background . Use that for notices that do not carry a state, and add color only when the message really is a success, a warning, or a failure.

Your export is queued. We email you when the archive is ready to download.
HTML 
<div class="message">Your export is queued. We email you when the archive is ready to download.</div>

Colors

Append a palette name to the base class. Each colored message mixes 10% of the palette fill into --r-surface-raised for the background and takes its text from --r-color-<name>-text , the text-safe version of the palette entry. That keeps the label readable in both themes instead of pairing a saturated fill with white text.

The same loop emits an outline variant with -outline appended: the background becomes transparent, the border and text use the palette text color, and the padding drops to 14px by 17px to absorb the border. Use the outline form when a tinted block would be too heavy, for example inside a card that already has a surface.

Extra padding

.message-extra-pad raises the padding to 27px by 30px, which gives the text the same 30px gutter on both sides instead of 20px on the left. Use it when a message holds a heading and a paragraph, or when it is the main content of a panel rather than a one-line notice.

Maintenance window

Reads stay available while we upgrade the primary database. Writes queue for about four minutes and replay automatically when the upgrade finishes.

HTML 
<div class="message message-info message-extra-pad">
    <strong>Maintenance window</strong>
    <p>Reads stay available while we upgrade the primary database. Writes queue for about four minutes and replay automatically when the upgrade finishes.</p>
</div>

Combining it with a close button still works, but the taller top padding leaves the button visually detached from the first line. Keep the default padding when a message is dismissible.

Dismissible message

.message-close is a transparent button pinned to the top right corner with 8px by 10px of padding, 18px text, and the --r-message-close-color token, which colored messages override with their own palette color. The base message already reserves the space for it.

On this site the removal is handled by the docs script: a message that carries data-doc-dismissible is removed from the document when its .message-close button is clicked. The framework ships no JavaScript, so the attribute is a docs hook, not a framework feature.

Your trial ends in two days.

    </button>
</div>

The close button needs type="button" so it cannot submit a surrounding form, and an aria-label because the icon carries no text. Removing the node is enough for a static notice. If the message is the only confirmation of an action, keep the outcome somewhere that survives the dismissal.

Messages with icons

The message module has no icon styles. An icon is ordinary inline content, so an inline SVG with stroke="currentColor" inherits the message color and needs no extra class. Keep the icon decorative with aria-hidden="true" when the sentence already states the outcome.

Payment declined. Update the card on file to restore the workspace.

An inline SVG sits on the text baseline, which is close enough for a 16px icon in 14px copy. If you need the icon in its own column, add a flex wrapper around the message content yourself; the module does not provide one.

JavaScript

roolith css ships no JavaScript. The snippet below is documentation only, and it is the behavior this page uses: find the closest message that opted in with a data attribute, then remove it. Delegating from the document keeps it working for messages added later.

JavaScript 
/**
 * Remove the dismissible message that owns the clicked close button.
 * @param {HTMLElement} button - The clicked close button.
 * @returns {void}
 */
function dismissMessage(button) {
    const message = button.closest('.message[data-doc-dismissible]');

    if (message) {
        message.remove();
    }
}

document.addEventListener('click', (event) => {
    const close = event.target.closest('.message-close');

    if (close) {
        dismissMessage(close);
    }
});

Bind to data-doc-dismissible or your own attribute, but keep the check: a message without the attribute should not disappear when a close button inside it is clicked, because that message may be a permanent notice.

Accessibility

A message already in the markup is read in place, so it needs nothing extra. A message that appears after an action needs to be announced, and that is a live region decision.

  • Use role="status" for a polite update such as a saved confirmation, and role="alert" for an error that should interrupt. Both imply a live region, so do not add a second aria-live to the same element.
  • Insert the live region into the document before you fill it, or update text inside an element that is already present. A region added at the same moment as its text is often not announced.
  • For a stack of messages, wrap them in a container with aria-live="polite" and aria-atomic="true" so the whole block is read as one update.
  • Do not move focus to a message. Announce it, leave the focus where the user was, and let them continue.
  • State the outcome in the text. The color and the tint reinforce the message, they do not carry it, and a colored block with no words tells a screen reader nothing.
  • The close button needs type="button" and an aria-label when it holds an icon. Without a label it is announced as "button".
  • Hiding a message with display: none removes it from the accessibility tree, which is what the dismiss snippet does. If the message is transient, make sure the same outcome is available somewhere else.

Class reference

The color classes are generated from the palette map, so the list below is the full set. Each one also has an outline partner.

Class Applies Notes
.message Base Block notice with 17px top and bottom padding, 20px on the left and 30px on the right, token radius, 10px vertical margins, and the neutral message background.
.message-primary Color Any palette name except white: secondary, tertiary, info, success, warning, danger, link, dark, black, light. 10% palette fill on the raised surface, palette text color.
.message-primary-outline Color variant Transparent background with a 1px border and text in the palette text color. Padding becomes 14px by 17px.
.message-extra-pad Layout 27px by 30px padding for messages with a heading and copy, so the copy gets the same gutter on both sides.
.message-close Close button Transparent button pinned to the top right with 8px by 10px padding and 18px text. Colored messages match their own text color.
