Modal

A modal is a dialog layer for a decision or a short form that must be finished before the page continues. The framework supplies the fixed overlay, the centered content box, the header, body, and footer slots, and the .active state that reveals them. Opening and closing is script.

class: .modal - defined in modules/_modal.scss
The default $modal-layout is css-grid, which centers .modal-content between two flexible spacer rows. traditional and flex change the internals of the same markup, not the class names.

Basic usage

.modal is the overlay: fixed to the viewport at full size, padded 20px on each side, painted with the --r-modal-background scrim, and hidden with display: none until it gains .active.

Inside it, .modal-content is the dialog box: a maximum width of 600px, the token radius, the content shadow, its own vertical scroll, and the fade-up animation. The header, body, and footer are ordinary slots, each padded with --r-modal-content-spacing (20px). The header carries a bottom border and a 16px bold title, the footer carries a top border and a 10px gap. The invite demo below sizes the box to an explicit 500px with an inline width, clamped by calc(100vw - 2.5rem) so it still fits the overlay padding on a narrow screen; the Sizes section covers the built-in presets, which only cap the max width.

The trigger is a normal button. Here it is wired with the docs hook data-doc-modal="#modal-invite", which adds .active to the matching overlay. The overlay markup sits after the code block, outside the demo box, because a fixed layer cannot be previewed inline.

HTML 
<button type="button" class="button button-primary" data-doc-modal="#modal-invite">
    Invite a teammate
</button>

        <div class="modal-header">
            <span id="modal-invite-title">Invite a teammate</span>
            <button type="button" class="modal-close" aria-label="Close dialog">
                <svg width="18" height="18" viewBox="0 0 24 24" fill="none" aria-hidden="true" focusable="false">
                    <path d="M6 6l12 12M18 6L6 18" stroke="currentColor" stroke-width="1.5" stroke-linecap="round" />
                </svg>
            </button>
        </div>

            <div class="form-field">
                <label class="form-label" for="invite-email">Email address</label>

</div>

Two notes on this page. The demo overlay carries an inline z-index: 1100 because the docs header is sticky at 1000, while the component itself uses z-index: 10. And the docs hook is only a hook: the framework knows nothing about data-doc-modal, so pick your own attribute in an application.

Sizes

Add small, large, or fluid to .modal-content. Small caps the box at 300px for a confirmation, large raises it to 800px for a wide form or a checklist, and fluid takes up to 80% of the padded overlay width for content that needs the room, such as the scrollable settings comparison below. The default 600px is a comfortable middle for a short form.

The large example uses .list for its checklist, and .modal-body itself adds token padding only. The sizes snippet abbreviates the close control to a text label, while the live demos use the icon SVG shown in the basic usage example.

The scrollable settings comparison sits in .table-responsive, which scrolls the overflow on the x axis. The wrapper needs role="region" and an aria-label whether or not the table overflows, and tabindex="0" while the table overflows, so a keyboard user can reach the scroll.

The modifiers only change max-width. The overlay stays padded by 20px on each side, so a fluid box is up to 80% of the padded overlay width and never touches the screen edge.

In the default grid layout the content row has no maximum height, so keep a dialog shorter than the viewport. The flex layout caps the box at 90% of the viewport height, and a tall grid dialog needs its own max-height before .modal-content can scroll.

Footer actions

.modal-footer is a flex row with a 10px gap, so a cancel and a confirm pair sits together without a bundle wrapper. Add .modal-footer-right to push the pair to the right edge, which is the usual pattern when the footer holds exactly one decision.

Keep the destructive action on the left of the primary one and give the primary action the stronger color. A dialog with a single action can drop the cancel button, since the header close button and Escape already dismiss it.

Without .modal-footer-right the actions stay at the start of the footer, which suits a footer that mixes a status line with one button.

Opening and closing

Only one class matters. The overlay is display: none until it has .active, and adding or removing that class is the entire open and close API. The docs script adds it from a data-doc-modal trigger, removes it from a .modal-close or [data-doc-modal-close] element, removes it when the overlay itself is clicked, and removes it on Escape.

A backdrop click means a click on the .modal element itself, in the space outside .modal-content. That space exists because the overlay is padded and the content is capped in width, so the listener must compare the event target with the overlay rather than with any ancestor.

Escape closes the topmost surface. The docs script returns focus to the trigger on Escape, on a close button click, and on a backdrop click, so the user lands back where the dialog started however it was dismissed.

HTML 
<button type="button" class="button button-primary" data-doc-modal="#modal-rotate-key">
    Rotate deploy key
</button>

<div class="modal" id="modal-rotate-key">

            <span id="modal-rotate-key-title">Rotate deploy key</span>
            <button type="button" class="modal-close" aria-label="Close dialog">

Open the dialog, then close it with the header button, the footer cancel, a click on the backdrop, or Escape. The same markup opens with nothing but class="modal active", which is useful when the server renders the dialog already open.

JavaScript

roolith css ships no JavaScript. The snippet below is documentation only, and it shows the open, close, and focus behavior: a trigger adds .active, and the close controls, the backdrop, and Escape all remove it and return focus to the trigger. The live page also re-runs the table gate when a modal opens, so a wrapper inside a hidden dialog regains its scroll stop, and the Table page explains that gate.

JavaScript 
const modal = document.querySelector('#modal-rotate-key');

let lastTrigger = null;

/**
 * Show the modal and remember the element that opened it.
 * @param {HTMLElement} trigger - Element carrying data-doc-modal.
 * @returns {void}
 */
function openModal(trigger) {
    lastTrigger = trigger;
    modal.classList.add('active');
    modal.querySelector('.modal-content').focus();
}

/**
 * Hide the modal and return focus to the element that opened it.
 * @returns {void}
 */
function closeModal() {
    modal.classList.remove('active');

    if (lastTrigger && document.body.contains(lastTrigger)) {
        lastTrigger.focus();
    }

    lastTrigger = null;
}

document.addEventListener('click', (event) => {
    const trigger = event.target.closest('[data-doc-modal]');

    if (trigger) {
        openModal(trigger);
        return;
    }

    if (event.target.closest('.modal-close, [data-doc-modal-close]')) {
        closeModal();
        return;
    }

    if (event.target === modal) {
        closeModal();
    }
});

document.addEventListener('keydown', (event) => {
    if (event.key === 'Escape' && modal.classList.contains('active')) {
        closeModal();
    }
});

Two details keep this usable. Focus moves into the dialog after it opens, and every close path, whether the close button, the backdrop, or Escape, returns it to the trigger so a keyboard user does not restart from the top of the document. The snippet does not trap Tab; the accessibility notes below explain why that matters.

Accessibility

The framework draws the layer; the dialog semantics, focus behavior, and Escape handling are yours. The list below is the minimum for a usable modal.

  • Put role="dialog" and aria-modal="true" on .modal-content, not on the overlay, and point aria-labelledby at the element that holds the title so the dialog has a name.
  • Move focus into the dialog when it opens. Focus the content box with tabindex="-1" or the first field, and keep Tab and Shift + Tab inside the dialog until it closes.
  • Return focus to the trigger on close, especially when Escape or the backdrop was used. A close button click also has to leave the user somewhere sensible.
  • Escape must close the dialog. Handle it at the document level while the dialog is open, and let a nested surface close first so one Escape never closes two layers.
  • The closed state is display: none, so a closed dialog is already out of the tab order and the accessibility tree. Do not replace it with an opacity or transform hide that leaves it focusable.
  • A backdrop click is a convenience, never the only way out. Keep a visible close button, give it type="button" and an aria-label when it holds an icon.
  • A wide table in a modal body should sit in .table-responsive with role="region" and an aria-label whether or not the table overflows, and tabindex="0" while the table overflows, so a keyboard user can scroll it. The Table page documents the same responsive-wrapper rule.
  • Stop the page behind from scrolling while the dialog is open. The framework scrolls .modal-content only and does not lock the document.
  • Avoid opening a modal from another modal. If the flow needs two steps, swap the content of one dialog or use a full page instead.

Class reference

Radii, spacing, scrim color, shadow, and borders come from the --r-modal-* tokens, so a theme changes the dialog without touching these classes.

Class Applies Notes
.modal Overlay Fixed full-screen scrim at z-index: 10 with 20px of side padding. Hidden until it has .active.
.modal.active Overlay state Switches the overlay to display: grid in the default layout, with the content between two flexible spacer rows.
.modal-content Dialog box 600px maximum width, token radius and shadow, own vertical scrolling, and the fade-up animation.
.modal-content.small Size Caps the dialog at 300px for a short confirmation.
.modal-content.large Size Caps the dialog at 800px for a wide form or a checklist.
.modal-content.fluid Size Takes up to 80% of the padded overlay width, useful for a scrollable settings comparison or other wide content.
.modal-header Header Token padding, a bottom border, and a 16px bold title on a 22px line.
.modal-body Body Token padding only. Fields, copy, lists, and other content are application markup, and the large example uses .list for its checklist.
.modal-footer Footer Token padding, a top border, and a 10px flex gap for the actions.
.modal-footer-right Footer modifier Pushes the actions to the right edge of the footer.
.modal-close Close button Pinned to the top right with token padding, 18px text, and a hover opacity change.
