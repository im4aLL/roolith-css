Block repeater

The repeater block arranges repeatable field rows as a list with a drag handle on the left and an optional action cell on the right. It styles the rows and the handle, and leaves sorting, adding, and removing to your application.

class: .block-repeater - defined in blocks/_block-repeater.scss

Basic usage

.block-repeater is the wrapper. It zeroes the bottom margin of any .form-field inside it, so the fields sit tight in a row. .block-repeater-list is the list itself, a ul in the canonical markup with 5px of padding above and 10px below.

.block-repeater-item is a flex row aligned to the bottom with a 10px gap, and 10px of margin below it except on the last item. .block-repeater-primary is a second flex row with the same gap, and it holds the fields for the row. .block-repeater-secondary holds the per-row action.

Custom fields

<div class="block-repeater">
    <div class="form-label">Custom fields</div>

The add button sits after the list, inside the wrapper, and uses the plain Button classes. The block does not generate it, so name it for the thing that is repeated.

Sort handle and cells

.block-repeater-sort is a button with no background and no border, a grab cursor, and a 16px font size. On hover it takes the accent color. It also gets a 40px minimum height and centers its content, so the handle sits on the same bottom edge as the fields.

.block-repeater-secondary gets the same 40px minimum height and vertical centering, so a small action button lines up with the fields without extra offsets. The SCSS hides that cell on the first item: .block-repeater-item:first-child .block-repeater-secondary is display: none. The demo below has one row, so its remove button is in the markup but not rendered.

Because the first row cannot show a remove action, treat it as the base row of the repeatable set. If your product needs to remove every row, add a modifier in your own CSS that restores the cell, rather than depending on the framework rule.

Sorting, adding, and removing

roolith css ships no JavaScript. The block styles the handle and the cells, and nothing else: dragging a handle does not reorder the list, and the add and remove buttons do not change the DOM.

Adding a row is a clone or template append, removing a row is a DOM removal, and sorting needs pointer events that track the handle or a dedicated list library. Keep the rendering in your own code and leave the framework classes as the presentation layer.

HTML 
<ul class="block-repeater-list" id="custom-fields">
    <li class="block-repeater-item"><!-- first row, from the demo above --></li>
</ul>

<template id="custom-field-row">
    <li class="block-repeater-item">
        <!-- sort handle and block-repeater-primary, as above -->
        <div class="block-repeater-secondary">
            <button type="button" class="button button-outline button-danger button-small" data-repeater-remove>
                Remove
            </button>
        </div>
    </li>
</template>

<button type="button" class="button button-outline" data-repeater-add>Add field</button>
JavaScript 
const list = document.getElementById('custom-fields');
const template = document.getElementById('custom-field-row');
const addButton = document.querySelector('[data-repeater-add]');

addButton.addEventListener('click', () => {
    const row = template.content.cloneNode(true);

    // Drop the placeholder ids before the row lands in the page.
    row.querySelectorAll('[id]').forEach((element) => {
        element.removeAttribute('id');
    });

    list.append(row);
});

list.addEventListener('click', (event) => {
    const removeButton = event.target.closest('[data-repeater-remove]');

    if (removeButton) {
        removeButton.closest('.block-repeater-item').remove();
    }
});

The snippet is docs only. It covers add and remove and deliberately leaves sorting out, because a pointer-based reorder needs position tracking, a placeholder element, and a move decision that this block does not define. Row ids must stay unique: either drop them as above and wrap each input in its label, or rewrite them per row.

Responsive stacking

Below 640px, which is the medium breakpoint, the item wraps instead of overflowing. .block-repeater-primary takes flex: 1 1 200px with min-width: 0 so it can shrink, and .block-repeater-secondary takes a full row with its content pushed to the end.

The fields inside .block-repeater-primary stay side by side, so two inputs plus the handle can still be tight on a phone. Switch the primary cell to a stacked layout in your own CSS when rows carry more than two fields, or move the secondary action into the same row as the handle on very narrow screens.

Accessibility

The block is a visual list, so the group label, the row names, and the keyboard path all come from your markup and script.

  • Wrap the repeater in a <fieldset> with a <legend> instead of a styled text line, so the group has a real name.
  • Give every sort button a specific name with aria-label, such as Reorder the company size field. Six identical revisit controls are useless in a screen reader list.
  • Do the same for remove buttons, and add the row index or field name so the action is unambiguous.
  • The grab cursor is pointer only. Provide keyboard reordering, either move up and move down buttons or a documented key combination on the handle.
  • Announce list changes in a polite live region when rows are added or removed, and move focus to the first field of a new row.
  • Keep focus visible on the handle and the action buttons. The SCSS draws no focus style of its own, so leave the global ring in place.

Class reference

Every class below belongs to the block. The fields, labels, and buttons inside the rows come from Form and Button.

Class Applies Notes
.block-repeater Wrapper Zeroes the bottom margin of any .form-field inside it.
.block-repeater-list List 5px of padding above and 10px below. Use a ul so the rows are a real list.
.block-repeater-item Row Flex row aligned to the bottom with a 10px gap. 10px of margin below, cleared on the last item. Wraps below 640px.
.block-repeater-primary Row cell Flex row with a 10px gap for the row fields. Below 640px it takes flex: 1 1 200px and min-width: 0.
.block-repeater-secondary Row cell Action cell with a 40px minimum height and vertical centering. Hidden on the first item.
.block-repeater-sort Handle Transparent button with a grab cursor, 16px font size, 40px minimum height, and an accent hover color. Style a drag affordance inside it.
