Block SVG map

The SVG map block paints a set of inline SVG paths and positions a tooltip near the pointer. It owns the fill, the hover fill, the stroke, and the tooltip box, and leaves the map geometry and the tooltip script to you.

class: .block-svg-map - defined in blocks/_block-svg-map.scss

Basic usage

.block-svg-map is a flex wrapper that centers its content. Every path inside it takes its fill from --r-block-svg-map-fill-color and its stroke from --r-block-svg-map-stroke-color, with a transition on the fill property. On hover the fill moves to --r-block-svg-map-fill-hover-color.

The default tokens are neutral 400 for the fill, neutral 500 for the hover fill, and the neutral color for the stroke, so the map reads as a quiet surface until the pointer lands on a region. Override those three tokens to recolor every region at once.

The demo uses a small schematic outline so the shape rules stay readable. The canonical world map in extended/blocks.html uses the same structure with one path per country and the same data-name, data-pageviews, data-unique-visitors, and data-visits attributes.

The hover fill is a CSS :hover rule, so it is pointer only. Keyboard focus gets no fill change from the framework, and the demo runs no script, which is why hovering here changes the fill and nothing else.

Tooltip

.block-svg-map-tooltip is a fixed position box pinned at the top left corner with z-index: 10, pointer-events: none, opacity: 0, and visibility: hidden. It carries 12px text over an 18px line height and never wraps. Padding, radius, background, text color, and the fade duration all come from the tooltip tokens.

The show class sets opacity to 1 and visibility to visible, and the change is transitioned over --r-block-svg-map-tooltip-transition-duration, which defaults to the 150ms tooltip duration. Nothing in the SCSS sets left or top beyond the initial zero, so the position has to come from script.

Inside the tooltip, .block-svg-map-tooltip-content-hl is 14px at the bold weight, and a .block-svg-map-tooltip-content-text that follows it gets 5px of top padding. On its own, -text has no declarations and inherits the 12px tooltip type. The .block-svg-map-tooltip-content wrapper is present in the canonical script but has no styles.

HTML 
<div class="block-svg-map-tooltip" id="region-map-tooltip">
    <div class="block-svg-map-tooltip-content">
        <div class="block-svg-map-tooltip-content-hl">North region</div>
        <div class="block-svg-map-tooltip-content-text">Pageviews: 120k</div>
        <div class="block-svg-map-tooltip-content-text">Unique: 42k</div>
        <div class="block-svg-map-tooltip-content-text">Visits: 180k</div>
    </div>
</div>

roolith css ships no JavaScript. This snippet is docs only, and the docs page does not run it, so the live map above never opens a tooltip. It pairs the tooltip with the map, reads the data attributes off the hovered path, and writes text nodes rather than HTML.

JavaScript 
const map = document.getElementById('region-map');
const tooltip = document.getElementById('region-map-tooltip');

// The tooltip is fixed, so client coordinates map straight to its inset values.
const position = (event) => {
    const gap = 12;
    const rect = tooltip.getBoundingClientRect();

    const overflowsRight = event.clientX + gap + rect.width > window.innerWidth;
    const left = overflowsRight ? event.clientX - rect.width - gap : event.clientX + gap;

    const overflowsTop = event.clientY - rect.height - gap < gap;
    const top = overflowsTop ? event.clientY + gap : event.clientY - rect.height - gap;

    tooltip.style.left = `${left}px`;
    tooltip.style.top = `${top}px`;
};

// Only the metrics that exist on the path are rendered.
const render = (path) => {
    tooltip.replaceChildren();

    const title = document.createElement('div');
    title.className = 'block-svg-map-tooltip-content-hl';
    title.textContent = path.dataset.name;
    tooltip.append(title);

    if (path.dataset.pageviews) {
        const metrics = document.createElement('div');
        metrics.className = 'block-svg-map-tooltip-content-text';
        metrics.textContent = `Pageviews: ${path.dataset.pageviews}`;
        tooltip.append(metrics);
    }
};

map.querySelectorAll('path').forEach((path) => {
    path.addEventListener('pointerenter', (event) => {
        render(path);
        position(event);
        tooltip.classList.add('show');
    });

    path.addEventListener('pointermove', position);
    path.addEventListener('pointerleave', () => tooltip.classList.remove('show'));
});

The order matters: render first, then measure and position, so getBoundingClientRect sees the new content. The element keeps its box while it is hidden by visibility, so the measurement is correct before show is added.

Accessibility

An SVG map is a picture made of shapes. Screen readers need a name for the whole map and a name for each region you make interactive, and keyboard users need a way to reach those regions at all.

  • Name the collection with role="group" and aria-label on the svg. Avoid role="img" when the paths are focusable, because it hides the children from assistive technology.
  • Put a <title> as the first child of each interactive path, so the region has a name without relying on the tooltip.
  • Add tabindex="0" to every interactive path. Give it role="link" or role="button", and handle Enter and Space, because a click handler alone is unreachable from the keyboard.
  • The framework styles path:hover only. Add a :focus-visible fill or outline in your own CSS so the focused region is visible.
  • Repeat the numbers somewhere in text. A tooltip that only appears on hover is not available to touch users, keyboard users, or screen reader users in reading mode.
  • Touch has no hover. Show the tooltip on tap and hide it on release, or open the region detail in a panel instead of a floating box.
  • Keep pointer-events: none on the tooltip so it never blocks the region underneath it.

Class reference

The block styles the wrapper, the paths, and the tooltip box. The geometry, the data attributes, and the positioning script are yours.

Class Applies Notes
.block-svg-map Wrapper Flex container that centers the SVG.
.block-svg-map path Region Fill, stroke, and a fill transition from the block tokens. :hover raises the fill to --r-block-svg-map-fill-hover-color.
.block-svg-map-tooltip Tooltip Fixed box at the top left with 12px text, no wrapping, no pointer events, and hidden by opacity and visibility. Position comes from script.
.block-svg-map-tooltip.show State Sets opacity to 1 and visibility to visible, transitioned over the tooltip duration.
.block-svg-map-tooltip-content Tooltip content Unstyled wrapper used by the canonical script to build the tooltip body.
.block-svg-map-tooltip-content-hl Tooltip content 14px at --r-block-svg-map-content-hl-weight, which defaults to the global bold weight.
.block-svg-map-tooltip-content-text Tooltip content No declarations of its own. Gets 5px of top padding when it follows a -hl element.
