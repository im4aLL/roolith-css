Block analytics

The analytics block is a three part panel: a header that pairs a title with a control, a body that holds a stat row or a stat table, and a footer for the next step. It supplies the spacing between those parts and nothing else, so the numbers come from another block.

class: .block-analytics - defined in blocks/_block-analytics.scss

Basic usage

.block-analytics-header is a flex row with space-between and centered items, so the title sits on the left and the control sits on the right. Put the control in .quick-menu when it switches between views, or use a single Button when it opens a setting.

.block-analytics-body adds 10px of padding above and below, which is half the block padding, and .block-analytics-footer adds 10px above only. A Block stat row fits the body without extra wrappers.

The .active class on the stat item paints the muted surface and a pointer cursor, which is the same treatment as hover. Keep it in sync with the view the control has selected, and mirror the selection in aria-current or aria-pressed.

With a stat table

The body takes any block that fits the width. A Block stat table is the usual choice for a ranked list, because the indicator bar and the trailing columns carry the comparison.

Use a .button or .quick-menu in the header, keep the title short, and let the footer hold one action. Two competing controls in a 600px panel leave no room for the title.

Structure and spacing

.block-analytics itself carries no declarations. The three part classes are global, not nested under it, so they also work when a page needs only the header or only the footer.

The block sets no width, background, border, or radius. Place it in a Box or a Card when it needs a frame, or drop it in a .column and let the column decide the measure. A panel narrower than about 600px makes a four item stat row cramped, so switch that body to a table or to two rows of stats.

The spacing chain is deliberate: the header sits on the top edge, the body adds 10px above and below, and the footer adds 10px above with none below. That keeps the footer close to the data it follows, and any outer padding in your container closes the block.

Accessibility

The block only positions three regions. The names, roles, and state of what you place inside them are your responsibility.

  • Keep the title on a real heading element. .block-analytics-hl has no styles, so the tag level is free and should match the surrounding page outline.
  • When the header control switches views inside the panel, mark the current item with aria-current="true" as well as .active, and announce the change in a live region.
  • The stat table is built from divs. Give it role="table", role="row", role="columnheader", and role="cell", or use a real <table>, so the values are read in context.
  • The indicator bar is decoration. Keep the number in a text cell, and do not let the bar width be the only way to compare rows.
  • Direction color is not enough. The arrow is drawn with a mask and the percentage is text, so the sign survives grayscale and screen readers.
  • Give the footer link a name that stands alone, such as View the full page report, because it is read out of context in a list of links.

Class reference

The block owns the three regions. The title, the controls, and the body content come from the components and blocks you place inside them.

Class Applies Notes
.block-analytics Wrapper Carries no declarations. The three part classes below are global and do not require this wrapper.
.block-analytics-header Header Flex row with space-between and centered items, so the title and the control sit on one line.
.block-analytics-body Body Half the block padding above and below, which is 10px by default.
.block-analytics-footer Footer Half the block padding above only, which is 10px by default.
.block-analytics-hl Header title Unstyled hook used by the canonical demo for the title. Any heading element works.
