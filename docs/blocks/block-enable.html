Block enable

A block enable card pairs a setting with its switch. It wraps a .box with a header, a body, and a footer that holds the control, then marks the enabled card with .is-active. The framework only styles the card; turning the setting on and off is application behavior.

class: .block-enable - defined in blocks/_block-enable.scss

Basic usage

The wrapper is a namespacing class: it only reaches into the Box module it contains. Inside the block, the .box element itself gets --r-block-enable-box-spacing padding, which defaults to half the block padding. The header, body, and footer keep their own box spacing, so the extra padding sits between the card border and the content instead of replacing the section padding.

The footer becomes a flex row with space-between, so the switch sits on the left and the documentation link sits on the right. Use the Form extended switch markup for the control and a text Button for the secondary action.

The footer text is 80% of its parent size and uses --r-box-footer-color, both from the Box module. Keep the switch label at its own 14px size, which the .form-switch-label rule already sets, so the control stays readable at the smaller footer scale.

Active state

Add is-active to the .block-enable wrapper, not to the box. The state tints the box background with --r-block-enable-active-background-color and repaints the border with --r-block-enable-active-border-color, which is the accent in the light theme and a lightened accent in the dark theme.

Everything else, including the padding override and the footer layout, still applies while the card is active, so the switch and the link never move between states.

The checked switch and the active card are independent. The switch input repaints the slider through the form module, and .is-active repaints the card, so nothing stops them from disagreeing. Keep them in sync in application code and treat the checked input as the source of truth.

Cards in a row

Wrap the cards in .block-grid to lay them out in equal columns with the block padding as a gap. The canonical demo shows one inactive card and one active card side by side to compare the two states.

Below 640px the cards land in one column, but that is incidental rather than designed. The base declaration is grid-template-columns: repeat(auto-fit, 1fr), which is not a valid auto-repeat track list, so browsers drop it and the grid stays on its default single column. From 640px up the block grid module sets repeat(auto-fit, minmax(0, 1fr)) with --r-block-padding as the gap, so the cards spread into equal columns.

Toggle behavior

roolith css ships no JavaScript, and this block is styling only. .is-active changes the card surface and border, and the checked state of .form-switch-input moves the slider; nothing connects the two. Application code must read the setting, update the class, and persist the change.

The snippet below wires the two states together. It assumes each card carries a data-block-enable hook and that the switch inside it is the source of truth. It is docs-only guidance, not part of the framework, and it is not loaded on this page.

JavaScript 
document.querySelectorAll('[data-block-enable]').forEach((card) => {
    const toggle = card.querySelector('.form-switch-input');
    if (!toggle) {
        return;
    }

    card.classList.toggle('is-active', toggle.checked);

    toggle.addEventListener('change', () => {
        card.classList.toggle('is-active', toggle.checked);
    });
});

Set the initial class on the server when you can, so the card does not flash the wrong state before the script runs. The script above still reapplies the class on load, which keeps the markup and the stored setting from drifting apart.

Accessibility

The card pairs a setting with the switch that controls it, so the control has to be a real form control with a name, and the card state has to be readable without the tint.

  • Use the checkbox behind .form-switch-input, or a button with role="switch", and give it an accessible name. The .form-switch-label text is that name, so keep it in the markup and keep it describing the setting.
  • Reflect the state on the control itself: checked for the checkbox, aria-pressed on a toggle button, or aria-checked alongside role="switch". .is-active only repaints the card and announces nothing.
  • Do not rely on color alone. The active border and background are a second cue on top of the control state, and the label text should already spell out Enabled or Disabled.
  • The switch input is transparent and sits behind the slider, so the framework draws no focus ring for it, and the card draws none either. Add a visible focus style on the slider, as the Form extended page shows, and do not replace the input with a styled div.
  • .is-active changes the background and the border only, so the footer stays put between states. Keep it that way when you add rules, because a control that moves on focus or on toggle pulls the body text away from the reader.

Class reference

The block targets the box inside it. The switch classes come from the Form extended module and are documented there.

Class Applies Notes
.block-enable Base Wrapper for one setting card. Requires a .box child.
.block-enable .box Box Adds --r-block-enable-box-spacing padding to the box element, on top of the section padding. The token is half of the block padding.
.block-enable .box-footer Footer Flex row with space-between, putting the switch and the secondary link at opposite ends.
.is-active State Applied to the .block-enable wrapper. Tints the box background with --r-block-enable-active-background-color and sets the border to --r-block-enable-active-border-color.
.form-switch Control The switch from the Form extended module. Put it in the box footer.
