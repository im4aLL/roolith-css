Block grid

A block grid places items in equal tracks and adds the block rhythm between them. It is the layout half of several blocks, including form rows and card groups, and it composes with any module that produces a card-sized block.

class: .block-grid - defined in blocks/_block-grid.scss

Basic usage

.block-grid is a grid container with a track list that only applies from 640px up. The base declaration is grid-template-columns: repeat(auto-fit, 1fr) , which is not a valid auto-repeat track list, so browsers drop it and the grid stays on its default single column. From 640px up the module sets grid-template-columns: repeat(auto-fit, minmax(0, 1fr)) and a gap of --r-block-padding , which is 20px at the default 1.25rem block rhythm.

minmax(0, 1fr) lets a track shrink below the intrinsic width of its content instead of forcing the grid wider than its container. The trade-off is that a long unbroken string can overflow its cell, so add overflow-wrap: anywhere or a min-width: 0 wrapper inside the item when the content is user supplied.

auto-fit is not a fixed column count. The browser resolves the tracks from the available width and collapses tracks that hold no items, which is what lets the same markup work in a narrow form column and on a full-width page.

There is no item class. Every direct child of .block-grid becomes a grid item, so the block-grid-item wrapper in the repository demos is optional and receives no styles of its own.

Responsive behavior

One breakpoint decides the layout: 640px. Below it only display: grid applies, because the invalid repeat(auto-fit, 1fr) declaration is dropped and the items land in one implicit column with no gap. That stacked result is incidental, not a designed fallback, so do not rely on it as a documented narrow-screen layout. At 640px and up the auto-fit track list and the --r-block-padding gap turn on together, so the spacing appears at the same moment the tracks do.

Resize the browser to see the change. If you need a fixed column count per breakpoint, use the grid module's .row and .columns spans, or set your own grid-template-columns on a wrapper around the block.

A .box has no margin of its own, so stacked boxes sit directly against each other below 640px. A .card keeps its 20px bottom margin, which is why a card grid still reads as separate items on a phone. Pick the composition with the spacing behavior you want at both widths.

Cards in a grid

Cards drop in without a wrapper: the grid sizes the track, the card fills it, and the card body supplies the padding and the type scale. The grid only decides the track width and the gap.

A card keeps its own 20px bottom margin. On a phone that margin is the space between stacked cards; when the grid puts items on more than one row it adds to the 20px gap. Set the margin to zero on the card when the gap has to be exactly --r-block-padding .

Stats in a grid

Stats are a common grid payload. Put a .stat inside a .card for the raised surface, then let the block grid handle the row. The stat centers its own text and supplies the header, body, and footer scale; the grid only decides how many of them share a row.

Keep the labels the same length across a stat row so the values line up, and avoid a second grid around a single stat. One grid with one card per stat is easier to reorder than nested grids.

The same layout carries form fields. Each .block-grid inside a block form pairs two fields, which is the canonical use of the class and the reason it has no background, border, or padding of its own.

Accessibility

The grid is layout only. It changes where the items sit, not what they are, so the semantics come from the DOM order and from the content of each item.

  • Keep the DOM order meaningful, because reading order follows the source and a grid can place items visually away from it.
  • Do not use explicit grid-row or grid-column placements that reorder the items. If the visual order has to change, change the markup order instead.
  • Keep each card heading in sequence and at a consistent level, so a reader can move between cards by heading.
  • Keep each card link or button descriptive on its own, since a list of controls is read out of context.
  • The grid adds no landmark and no list semantics. When the items form a set, put them in a <ul> and label the list when the page holds more than one.

Class reference

The block defines a single layout class. Everything inside it belongs to the component you place there, and the spacing token belongs to the block layer.

Class Applies Notes
.block-grid Wrapper display: grid . The base repeat(auto-fit, 1fr) is an invalid auto-repeat track list and is dropped, so below 640px the grid sits on the default single column. From 640px up: repeat(auto-fit, minmax(0, 1fr)) tracks with a --r-block-padding gap.
.card , .box , .stat Composition Any direct child becomes a grid item. Cards carry a 20px bottom margin; boxes and stats do not, so the gap only exists from 640px up.
