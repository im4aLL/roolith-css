Block auth

Block auth is the full screen scaffold for sign in, sign up, and password reset pages. It centers a 400px column on a full viewport height, then leaves the header, form, and footer to the existing form and button modules.

class: .block-auth - defined in blocks/_block-auth.scss

Basic usage

The wrapper takes the block padding top and bottom, centers its content on both axes, and sets min-height: 100vh. The container is a fixed 400px wide column with auto side margins, which is narrow enough for a single field column and wide enough for a full label and input pair.

Inside the container, three children do the work: .block-auth-header for the heading and the supporting line, the form itself, and .block-auth-footer for the secondary link. The header adds 30px of bottom padding and the footer adds 10px of top padding, both derived from --r-block-padding.

Welcome back

Sign in to the deployment dashboard.

Forgot your password? Reset password

The demo above overrides min-height with an inline style so the block fits inside this page. The code block keeps the unmodified markup; in a real sign in page the 100vh minimum fills the viewport.

The canonical demo also puts descriptive classes on the heading, the supporting line, and the footer link. _block-auth.scss defines none of them, so this page uses plain elements and normal anchors instead. Style those pieces with your own type and link rules.

Sign in form

The scaffold holds any form. The markup inside the container is the shared Form and Button work: .form-field for the row and its 20px bottom margin, .form-label and .form-input for the pair, and .button-block so the submit action fills the column.

This example adds a remember me checkbox from the Form module and a sign up line in the footer. The password field keeps the toggle from Form extended, which the framework positions but does not wire up.

The container has no surface, border, or shadow. On a sign in page that needs a card, wrap the form in a Card or a .box inside the container instead of styling the container, so the block keeps its single job of centering the column. This demo overrides min-height for the same reason as the previous one; the code block keeps the unmodified markup.

Field states and errors

The form module carries the state classes. Add error to the .form-field wrapper and the label, the input border, and the helper text switch to --r-form-error-color. success and warning work the same way.

Put the message in a .form-text element inside the same field. It renders as an 11px block with an 8px top padding, so the message sits directly under the input instead of pushing the next field away. The same field markup works inside the auth container.

Enter a complete email address.
HTML 
<form action="#" class="form">
    <div class="form-field error">
        <label class="form-label" for="email">Email</label>
        <input
            type="email"
            class="form-input"
            id="email"
            name="email"
            autocomplete="email"
            value="hadi@"
            aria-invalid="true"
            aria-describedby="email-error" />
        <span class="form-text" id="email-error" role="alert">Enter a complete email address.</span>
    </div>

    <div class="form-field">
        <button class="button button-primary button-block" type="submit">Send reset link</button>
    </div>
</form>

The error class is visual only. The aria-invalid attribute, the aria-describedby reference, and the live announcement are what make the state usable with a screen reader, and all three have to be managed by application code when validation runs.

Accessibility

The block is layout only, so the semantics come from the markup you put inside it. A sign in page is the primary content of the document, which means the wrapper should be the page landmark rather than a decorative div.

  • Make the scaffold the main landmark. On a real page use <main class="block-auth">, or give the wrapper role="main". The docs demos keep a div because the page already has a main landmark.
  • Name the region. Give the container aria-labelledby pointing at the heading in .block-auth-header, and keep one h1 per page so the heading order starts at the top level.
  • Label every input with a real <label for> in .form-label. A placeholder is not a label: it disappears on input and is not reliably announced.
  • Set the right autocomplete values (email, current-password, new-password) and use type="email" so mobile keyboards and password managers work.
  • Give the password toggle an aria-label and an aria-pressed state, and change the label when the input type changes. The toggle is a plain button, so it needs script to switch the type.
  • Use type="submit" on the form action. A button inside a form defaults to submit, but being explicit prevents accidental submits from buttons added later.
  • Announce errors. Put the message in the same field, connect it with aria-describedby, set aria-invalid="true" on the input, and move focus to the first invalid field after a failed submit.
  • Do not rely on the error color alone. The message text states the problem, and role="alert" on a message that appears after submit announces it without a focus change.
  • Make the footer links descriptive on their own. Reset password and Create an account are fine; avoid a bare Click here, and do not nest interactive elements inside each other.

Class reference

The block owns four classes. Form and button classes inside the container belong to their own modules.

Class Applies Notes
.block-auth Base Flex wrapper, centered on both axes, with the block padding top and bottom and min-height: 100vh.
.block-auth-container Column Fixed 400px width with auto side margins.
.block-auth-header Header Adds 30px of bottom padding, which is one and a half times the block padding.
.block-auth-footer Footer Adds 10px of top padding, which is half the block padding.
