Block header

A block header opens a page: a breadcrumb trail, the page title with optional supporting text, and the actions that apply to the whole page. The block owns the vertical rhythm and the switch from a stacked column to a two-sided row, while the breadcrumb, heading, and action menu keep their own component styles.

class: .block-header - defined in blocks/_block-header.scss

Basic usage

.block-header is the outer wrapper. It adds --r-block-padding of space below the header and gives a nested .breadcrumb half of that as bottom padding, so the trail is separated from the title without an extra wrapper.

.block-header-container does the layout: a wrapping flex column with a --r-block-padding gap and half of that padding above. From 640px up it becomes a row with justify-content: space-between, so the title sits on the left and the actions on the right.

.block-header-secondary holds the actions and is capped at max-width: 100%. Below 640px it takes the full width and its .action-menu-list switches to a wrapping row, which keeps every command reachable without horizontal scrolling.

All spacing comes from one token. --r-block-padding is 1.25rem by default, which produces the 20px below the block, the 10px below the breadcrumb, the 10px above the container, and the gap between its two sides. Override it on the block for a tighter header, or on :root to retune every block that shares the rhythm.

Primary action menu

.action-menu-primary on the .action-menu root turns each link into a stacked tile: the link becomes a column capped at 150px, the label centers under the icon, and .action-menu-icon grows to 18px. It suits a short set of commands whose icons carry most of the meaning.

This page loads Iconoir from a CDN in the head, and the demos put an <i> with the glyph class and .action-menu-icon inside each link. The block only spaces the icon, so any icon set that paints with color works the same way.

Action-led header

Many pages do not need a trail. Drop the breadcrumb and the container keeps its half padding above, so the header still separates from the surface above it. The heading becomes the first thing a reader hears and sees.

Put the primary actions in .block-header-secondary. A .button-bundle is the right wrapper for a cancel and save pair, while an action menu suits several low-emphasis commands. Both keep their own component spacing inside the header.

Invoices

12 open invoices across 4 teams, due by the end of the month.

HTML 
<div class="block-header">
    <div class="block-header-container">
        <div>
            <h3>Invoices</h3>
            <p>12 open invoices across 4 teams, due by the end of the month.</p>
        </div>
        <div class="block-header-secondary">
            <div class="button-bundle">
                <button class="button button-outline" type="button">Save draft</button>
                <button class="button button-primary" type="button">Send invoices</button>
            </div>
        </div>
    </div>
</div>

The small-screen rule still applies to this markup. Below 640px .block-header-secondary stretches to the full width of the column, and the bundle sits under the title with the same block gap above it. The buttons keep their intrinsic width, and .button-bundle does not wrap, so give the bundle a wrapping rule of your own if the pair has to survive a very narrow screen.

Responsive stacking

One breakpoint at 640px changes the header. Below it the container is a column, the secondary is full width, and the action list is a row that wraps. At 640px and up the container becomes a row with space-between, and the action list is a row by default.

Long labels are the stress case. The secondary is capped at max-width: 100%, so it never takes more than the room the container gives it, and the list wraps between items below 640px. Keep command labels short: there is no truncation rule, and one very long unbreakable word can still force the header wider than the page.

Accessibility

The header holds three navigation-relevant pieces: the trail, the page heading, and the action group. Structure each one for assistive technology instead of relying on its position.

  • Give the page exactly one <h1>. These demos use <h3> because this documentation page already has an <h1>; in an application the title inside .block-header-container is normally the page <h1>.
  • Wrap the breadcrumb in <nav aria-label="Breadcrumb"> and keep the ordered list. Put aria-current="page" on the current item, because .active is visual only.
  • Give every <nav class="action-menu"> a label that describes the group, such as "Report actions", so the landmark list stays useful when a page has more than one menu.
  • The icon font glyph is decoration. Hide it with aria-hidden="true" and let .action-menu-label name the link; the glyph has no accessible name of its own.
  • Keep the source order trail, heading, then actions. At wide widths the actions sit on the right, but both reading and tab order still reach them after the heading.
  • Let the heading wrap rather than truncating it, and keep the supporting line as a real paragraph so it is announced in context.
  • Use a link for navigation and a button for an action. The header changes layout, not element semantics.

Class reference

The block defines three layout classes and repeats one rule for the action menu label. The breadcrumb and action menu classes come from their own modules and keep their own documentation.

Class Applies Notes
.block-header Wrapper Bottom padding of --r-block-padding. A nested .breadcrumb gets half of that below it.
.block-header-container Layout Wrapping flex column with a --r-block-padding gap and half of it above. A row with space-between from 640px up.
.block-header-secondary Layout max-width: 100%. Below 640px it is full width and its .action-menu-list becomes a wrapping row.
.action-menu-label Action menu Sets user-select: none. The action menu module declares the same rule.
