Platform

Delivery infrastructure without the infrastructure.

Kite sits between your application and your customers' endpoints, so your code sends one request and your team stops owning a retry queue, a signature library, and a dashboard nobody wants to build.

01

Signatures

Signed on the way out

Every request carries an HMAC-SHA256 signature over the exact bytes we send. Rotate a secret without dropping a delivery, and check it with one SDK helper or any standard crypto library.

Kite-Signature: v2=c0f4...8a1

02

Reliability

Retries that end

Twelve jittered attempts across 24 hours, then a dead-letter queue that keeps the last response we received. A 4xx other than 429 stops the sequence, because a malformed payload will not heal.

attempt 3 of 12 - backoff 8s

Support

Questions from the support queue.

Still stuck? Search the error codes or write to support@kite.dev, where a delivery engineer answers.

How many times does Kite retry a failed delivery?

Twelve attempts with exponential backoff and jitter spread over 24 hours. A 4xx response other than 429 stops the sequence immediately, because retrying a malformed payload only wastes your endpoint's time.

Can I verify a signature without the SDK?

Yes. We sign a standard HMAC-SHA256 digest of the timestamp and the raw request body, so any language with a crypto library can check it. The verifier guide lists the exact string we sign for each event.

What happens when an endpoint is down for a day?

The event lands in the dead-letter queue with the last response we received. Replay it from the dashboard, the CLI, or the API once the endpoint is healthy again, and the attempt counter keeps its history.

Which regions do deliveries leave from?

Kite delivers from the region closest to your endpoint across 34 locations. Payloads rest in the region you choose when the workspace is created, and EU workspaces keep their logs in the EU.

How do I migrate from my own retry queue?

Drain your existing queue into the migration endpoint, keep both paths live for a week, then compare delivery counts and response codes in the logs before you switch the last endpoint over.
